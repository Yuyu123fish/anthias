# Feature 012：Agent 运行对象与工具组织

状态：已实现

## 开发者速览

> **一句话**：让单个 Agent 的状态、能力与运行资源有明确持有者，并集中工具及会话内部职责。<br>
> **核心做法**：参考 Pi 的 Agent/state/context 关系，工具定义与执行计划同源，Git 归入基础工具。<br>
> **边界**：保持公开 Agent 行为、权限、并发、事件和 Session 存储合同。<br>
> **风险 / 未验证**：重点验证请求工具快照、持久化顺序、取消和共享资源关闭。<br>
> **当前 / 请审阅**：实现、本地验证与独立审查完成，等待开发者验收。

## 问题

当前 SessionAgent 的消息、审批、Run 和关闭状态散在工厂闭包中，完整运行环境只能沿多个装配调用追踪。基础 Tool 的定义、名称分派和执行实现分别维护；Git 已有完整受管行为，但目录与基础工具分离。Session 的 Schema 编码及清理恢复也混在较大文件中。

基线为 `main @ c7b8853`。已有 Runtime 装配、Session writer、Tool batch、Context 投影和请求级 MCP 快照继续作为实现起点。

## 已确认决定

1. 单个根或成员的 SessionAgent 是完整运行对象：集中实际状态并持有模型、上下文、工具、Session、权限引用和 Run 资源。公开 Agent 保留稳定会话入口。
2. 参考 Pi 的状态持有与上下文快照思想，保留普通工厂函数。持久历史、模型投影和公开只读状态有明确来源，不建立另一份可任意回写的事实。
3. 一个工具对象同时提供模型定义和执行计划；模型可见列表与实际分派从同一组对象得到。工具可见性不能替代授权。
4. Git 实现及其 Tool 适配进入 `tool/basetool/git/`；Git 自己提供 GitWorkspace 类型。根事实、受管 worktree、进程级写入串行化和执行前复核保持。
5. write_file 与 edit_file 保持两个文件、两个行为，继续复用文件变更底层。
6. Session writer 保持独立；分离 Message 持久编码转换、清理恢复状态协议，并集中只读查询入口。

## 用户与调用方行为

创建、切换和恢复会话后，用户仍通过同一个 Agent Interface 提交任务、确认工具、停止和关闭。根与成员采用相同单 Agent 结构；只读成员限制和授权来源不因装配统一而改变。新增基础工具时，定义、参数合同和计划入口在工具自身集中，装配只选择工具。

## 行为与失败合同

- 工具维持参数校验、策略、准备、审批、执行前复核、结果收口的既有顺序；文件并发冲突与四 worker 上限保持。
- MCP 工具和执行计划绑定同一次请求的可见快照；连接 generation/schema 仍在执行前检查。
- 完成消息刷盘成功后才进入运行内存投影及公开完成事件；Run 终态唯一，先等待已接受写入，再归还 lease。
- 取消与关闭等待已拥有的任务、工具和写入收口。成员不关闭共享 MCP、共享权限或整组资源；整组关闭先成员后根。
- 保留 Schema 1/2/3、旧平铺、新嵌套与混合 Session 布局；只读查询不执行恢复副作用，不要求 Workspace 存在。
- 清理继续整组取锁后重验，先持久化 pending 再移动；来源或归属不确定时保留，永不删除 Git 目录或分支。
- package 入口的生产工厂、公开类型和控制行为保持；模型执行器、Provider、工具执行函数和持久化句柄不进入 TUI。

## 不在范围内

不增加产品功能、Provider、OS 沙箱、通用插件 Registry、数据库或新 Session Schema；不改变用户的 Git 操作授权；不进行真实模型、外部 MCP/SearchAPI 调用或人工终端体验验收。
