状态：已实现

## 问题

实施前基线已有线性 Session、上下文压缩和 Skill / MCP 来源持久化，当时有三个实际缺口：

- 用户需要在不同会话重复说明偏好，经过验证的项目经验也没有统一的跨会话积累、查询、纠正和遗忘入口。
- 项目 AGENTS.md 尚未自动加载；动态来源正文在历史前方重新拼装，容易改变已有请求前缀。新增记忆若沿用同样方式，会继续扩大这一问题。
- 单个 Run 的 12 次普通模型请求限制，以及根与成员共享的 60 次模型调用限制，会让仍在推进的任务提前结束；无成员的根任务也受共享限制影响。

本 Feature 形成“取得可靠信息 → 保存记忆 → 按范围和时效采用 → 更新或遗忘”的闭环，并明确对话历史如何组成下一次模型请求。

## 用户流程

1. 作为开发者，我希望新会话自动采用当前项目规则和适用的个人偏好，以便减少重复说明。
2. 作为开发者，我希望 Agent 记住我明确表达的长期要求，以便后续任务保持一致。
3. 作为开发者，我希望 Agent 将已经验证的项目事实和解决方法保存为经验，以便其他会话能够复用。
4. 作为开发者，我希望猜测、冲突和未经验证的内容有明确状态，以便它们不会被当作可靠结论使用。
5. 作为开发者，我希望通过 /memory 查看、确认、纠正或遗忘记忆，并控制自动记忆开关，以便掌握实际保存的内容。
6. 作为开发者，我希望 Agent 根据当前问题主动查找相关记忆，以便无需每次手动打开管理入口。
7. 作为开发者，我希望临时要求到期后停止采用，项目条件变化后重新核验经验，以便旧信息不会持续影响工作。
8. 作为开发者，我希望不同项目的经验相互隔离，同一仓库的工作树能够复用适用经验，以便兼顾共享与准确性。
9. 作为开发者，我希望规则和记忆的修改在后续请求中及时生效，以便当前任务遵循最新有效信息。
10. 作为开发者，我希望查看历史时看到当时实际发生的内容，继续任务时采用当前有效规则，以便理解过去并正确推进后续工作。
11. 作为开发者，我希望压缩、重启和并发会话不会丢失纠正或恢复已遗忘内容，以便记忆状态可信。
12. 作为开发者，我希望来源加载和普通续聊尽量复用已有请求前缀，并能区分本地检查与实际缓存收益，以便判断优化是否有效。
13. 作为开发者，我希望仍在推进的任务不会因累计调用次数停止，同时保留主动停止和失败提示，以便完成较长任务。
14. 作为开发者，我希望读取、保存或恢复失败时得到明确结果，以便知道哪些记忆已经生效、哪些操作需要重试。

正常流程为：开始或明确继续 Session，核对项目与有效来源；Agent 在当前 Run 中查询和维护记忆；来源变化先保存，再进入后续请求；结束后由 /memory 管理同一份持久数据。

## 已确认决定

| 方面 | 合同 |
| --- | --- |
| 分层与落点 | 两类记忆统一保存在 Anthias 项目根目录的 memory/；用户记忆保存偏好、习惯和长期要求，经验记忆保存可复用的项目事实、解决方法与适用条件 |
| 双入口 | 用户通过 /memory 管理；Agent 可以主动查询和维护，双方使用相同的数据、作用域和有效性规则 |
| 项目规则 | 自动加载当前任务项目的 AGENTS.md；它继续以项目文件为准，不复制成可由记忆维护行为修改的项目规则 |
| 冲突顺序 | 先判断适用性与有效性，再按“项目规则 > 有效经验记忆 > 用户记忆”处理冲突；当前真实用户要求优先于这三类来源，运行时权限与硬禁止仍独立生效 |
| 普通更新 | 用带来源、版本及替代关系的追加内容表达变化，不在每轮请求时改写早期消息；需要停止发送的内容通过过滤或重建移除 |
| 历史映射 | Session 保存会话事实，memory/ 保存跨会话记忆，Context 选择并编排下一次请求；压缩不覆盖原始聊天历史 |
| 持续运行 | 移除单 Run 的 12 次和根、成员共享的 60 次调用截止，不用另一个更大的固定次数替代 |
| 压缩范围 | 保留已有自动与手动压缩主线；只补齐来源、身份和恢复合同，不恢复归档调查中的主动整理、草稿摘要等整套提案 |

### 首版默认行为

以下首版默认行为已随 Spec 和目录方案获得开发者确认：

- 自动记忆默认开启，开关作为 Anthias 的本地设置跨会话保存。关闭后停止自动提取和内容更新；已有记忆查询、有效性过滤，以及用户明确要求的保存、纠正和遗忘仍可用。
- Plan 模式允许查询和受管记忆维护，视为 Anthias 应用数据维护；这不开放任务 Workspace 的写入，也不允许修改 AGENTS.md 或借记忆获得执行授权。用户明确要求不保存时遵从该要求。
- 明确的用户长期要求可以直接形成用户记忆；有可核查证据的经验可以进入可用状态。对行为的单次推断、含糊偏好和证据冲突先保留为候选或待复核，不默认注入为确定事实。推断出的偏好需要后续真实用户确认才能转为可用，无需为每次明确要求的保存另加确认。
- 主动维护发生在现有 Run 内，通过受管行为完成；首版不在任务结束后另起后台整理 Agent 或隐藏的模型调用。
- /memory 的查看可在运行中使用；人工修改和开关切换沿用现有空闲时控制边界，忙时明确返回需要先停止再重试，不悄悄排队。Agent 自身的维护在其所属 Run 内执行。
- 首版自动加载任务项目根目录的 AGENTS.md，不扫描嵌套目录继承；不设置所有记忆通用的固定天数有效期。

## 记忆、范围与时效

### 存储与项目身份

memory/ 是 Anthias 应用侧的统一存储根，与启动时选定的任务 Workspace 分开。运行时数据应默认排除在版本控制之外；本 Feature 不把开发者的记忆提交到代码仓库。

同一 Git 仓库的工作树通过共同仓库身份归组，分支、文件版本或环境相关的经验仍须匹配各自条件。AGENTS.md 读取当前工作树自己的根目录版本。非 Git 项目按规范化后的明确 Workspace 路径区分，不根据目录名猜测项目，也不要求存在 Git 提交才能使用记忆。

默认查询当前项目与跨项目适用的用户记忆；其他项目的经验不会自动注入。只有用户明确表达的通用要求才默认成为跨项目偏好；“这个项目”限定当前项目，“这次”优先保留在当前任务，不自动扩大范围。首版经验记忆默认归属当前项目。

分类依据是内容，而不是写入者。用户提供的项目事实属于经验记忆，并标明“用户提供”；它不能因此被标成 Agent 已执行验证。用户记忆也可以由 Agent 从用户表达中自动提取。

每条记忆至少具有以下信息；具体字段名、文件布局和序列化格式由 Plan 确定：

| 信息 | 用途 |
| --- | --- |
| 稳定条目身份、修订版本、类别与正文 | 区分新增、补充、替代和重复提交 |
| 用户或项目范围、分支及环境等适用条件 | 判断当前任务能否采用 |
| 来源及必要证据说明 | 区分用户明确表达、实际核验与推断；能关联原会话消息、文件或 Tool 结果时保留引用 |
| 创建、内容更新与最后确认时间 | 显示产生和复核过程；读取时间不冒充确认时间 |
| 有效状态，以及适用的截止时间或复核条件 | 表达可用、候选、待复核、过期和遗忘等区别 |
| 替代关系或最小遗忘标记 | 防止旧版本、迟到候选和历史整理覆盖已生效的纠正或遗忘 |

凭据、令牌等敏感值不进入记忆；不为证明一条经验复制整段日志或完整会话。源 Session 清理后，已经保存的独立记忆不会被级联删除，但需要保留必要的非敏感证据说明，并明确原始引用可能已不可读取。

### 主动获取与更新

Agent 在遇到明确的长期要求、用户纠正，或取得可复用的可靠结论后发起维护。维护先查询相关条目，再决定补充、替代、保留候选或新增；相同来源和内容的重复读取不产生新条目，也不不断延长有效期。

例如，用户提出“以后回答先给结论”，可以保存为用户偏好；用户只说“这次简短一点”，默认只约束当前任务。Agent 实际发现某个测试命令需要特定目录和环境，并验证了该命令的结果后，可以保存“命令、运行条件、验证范围和来源”；只想到一个可能有效的修复方法时，仍留在任务或候选中。

代码、配置的直接核对只能支撑它们确实证明的事实；命令退出成功也不能自动扩大成“整个项目已经验证”。有明确相反证据时替代旧结论；证据不足以判断时标记待复核，不静默合并成确定结论。

保存成功后才报告“已记住”并发布相应状态。保存失败保持原记忆，不影响用户当前明确指令本身的约束力。关闭自动记忆不会阻止用户通过 /memory 或明确的自然语言要求修改记忆。

### 时效如何生效

| 内容 | 生效与复核方式 |
| --- | --- |
| 明确的长期偏好 | 默认长期有效，直到用户纠正、遗忘或适用范围改变 |
| 有期限的临时要求 | 保存可判断的绝对时间或结束条件，到期后退出默认采用；无法确定期限时不擅自转为永久要求 |
| 与项目有关的经验 | 使用前匹配关联的项目、版本、配置或环境条件；关键条件变化或无法确认时，先复核再采用 |
| 推断或冲突内容 | 不作为确定事实默认注入；用户确认或新的独立证据满足条件后才能转为可用 |
| 明确要求定期复核的内容 | 到复核时间进入待复核；时间变旧不直接等同于事实错误，也不自动删除 |
| 已遗忘内容 | 停止检索和注入，并抑制来自旧来源、旧候选及摘要的自动再生成 |

日期计算使用明确时间基准和时区；读取、命中缓存、模型再次复述或摘要引用都不更新最后确认时间。重新核验必须关联新的真实证据，不能用“再次看到了这条记忆”替代。

新会话、继续任务及每次普通请求准备时核对已采用记忆的状态。到期、条件不匹配或待复核的内容退出有效来源；Agent 可以查阅其状态并取得新的证据，不得继续按已确认事实行动。有效期与 Provider 缓存存活时间互不替代。

### 纠正与遗忘

普通纠正保留条目身份并生成新版本，后续上下文明确新版本替代旧版本。已有历史仍能显示当时采用过旧版本；新会话和压缩重建采用当前有效版本。

遗忘成功后，可用记忆库不保留被遗忘的正文；允许保留必要的身份、来源范围和抑制标记。旧会话、旧摘要、成员迟到候选和其他进程的旧版本不能让该记忆重新可用。只有用户在遗忘后重新明确要求记住，才允许重新建立有效内容。

后续请求必须移除相应记忆注入及受影响的派生摘要，不能只追加一句“已忘记”。如果用户明确要求某段内容不再发送，还须从原始消息的模型投影中排除对应内容，必要时重建上下文；原始 Session 的物理擦除是另一项操作。遗忘记忆不会修改项目的 AGENTS.md，也不能假称同样内容已经从其他独立来源中删除。

更新以持久化成功后的请求准备边界生效。已经发出的模型请求无法撤回；在发现已采用来源被遗忘或要求停止发送后，取消受影响的生成，不执行其尚未执行的 Tool，重建后才能继续。已经执行的副作用按原事实保留，不承诺自动撤销。其他活动会话同样必须在后续请求和执行未开始的 Tool 前检查这类撤销。

## 项目规则与提示词编排

### AGENTS.md 自动加载

开始新会话时读取任务项目根目录的 AGENTS.md，保存本会话采用的来源快照；活动会话在下一次普通请求准备时检查文件变化，只为真实变化保存并追加新版本。明确继续任务或压缩重建时采用经过核对的有效版本。

文件不存在是正常状态；文件后来创建、删除或变更，都应形成有明确含义的来源更新。文件存在但读取失败，或完整规则无法放入允许预算时，应显示原因并暂停本次模型请求，不能静默截断规则、假装已加载或冒用旧版本。只查看历史时不检查当前文件来改写过去。

同一事项发生冲突时，按“当前真实用户要求 → 项目规则 → 有效经验记忆 → 用户记忆”解释；运行时权限检查独立执行。来源内的命令、授权声明或模型角色标签都不能扩大权限。

### 初始排列顺序

tools 保持独立请求字段。以下规定 Anthias 能控制的文本装配次序，不声称能控制 Provider 内部最终的工具序列化位置：

| 顺序 | 内容 | 稳定要求 |
| --- | --- | --- |
| 1 | Anthias 固定基础规则 | 置于 system；声明行为边界、来源优先级和记忆使用规则 |
| 2 | 少量稳定的用户记忆摘要 | 只含适用的明确通用偏好；保持条目选择与排列确定 |
| 3 | Workspace、平台、Shell 与初始权限模式 | 保存会话初始环境视图；实际执行仍核对当前权限 |
| 4 | 当前任务项目的 AGENTS.md 快照 | 保存初始采用的版本，不随普通请求重写 |
| 5 | 可用 Skill 等能力的紧凑目录 | 只保留发现所需元数据；正文按需加载 |
| 6 | 相关经验记忆的紧凑索引及少量有效条目 | 按项目、条件、相关性和预算选择 |
| 7 | 真实对话、Tool 结果、成员输入及动态来源 | 按会话进展追加，保持完整 ToolCall / ToolResult 组 |

用户记忆排在项目内容之前是为了复用稳定内容，它的冲突优先级仍然最低。第 2 至 6 项构成有界初始快照；首次选择后，普通检索和刷新不得回头改写这些块。有效状态的变化通过后续更新表达，压缩或必要重建时再折叠为当前快照。

工具集合不变时，名称、描述、schema 和顺序保持确定；工具增删、连接与权限变化必须如实更新。固定前方内容不放每轮时间、随机 Session 标识、最后读取时间或实时进度。持久记录 ID 用于内部关联，不要求原样渲染为提示词。

按需读取的 Skill、MCP 和记忆正文在对应读取完成后追加，同一正文不同时完整出现在 Tool 结果和另一个来源块中。重读同一已采用版本可以返回引用或状态；真正变化再保存新版本及替代关系。不能为注入来源伪造 ToolCall 或 ToolResult。

### 预算与缓存效果

初始用户摘要、经验索引、单次正文读取和单次维护都有明确上限；具体数值由 Plan 根据现有模型预算与基线确定。选择顺序必须确定，可用记忆过多时优先减少低优先级、低相关性的内容，保留可查询的索引与省略提示；不能无限扩大初始前缀。

记忆和来源正文无论放在 system 还是消息中，都计入同一请求预算。普通更新、压缩、遗忘、模型与工具变化各有明确原因；不能为维持缓存而保留不该继续发送的内容。

本地验收检查相同工具集合下的装配确定性，以及普通追加前后已有前缀是否保持。实际缓存效果使用 Provider 返回的用量，按可比较的输入 token 汇总，未知值保留未知，不用各轮百分比的简单平均冒充总体命中率。普通回复、摘要和审批保留各自统计边界，评估同时记录记忆维护产生的调用与总输入开销。

首版不承诺固定命中率或费用降幅；确定性本地验证不能替代真实 Provider 对照。

## 对话历史与上下文映射

### 三类数据的职责

Session 是会话事实记录，memory/ 是跨会话当前记忆，Context 是下次请求的工作视图。TUI 从会话记录呈现真实对话与来源提示；模型接收经过选择、压缩和编排的投影。二者共用事实依据，不维护两份可以独立修改的聊天历史。

| 会话中发生的内容 | Session 保存 | 下一次请求如何使用 |
| --- | --- | --- |
| 用户、Assistant 和 Tool 消息 | 原消息、entryId / seq、实际 Tool 调用身份及结果状态 | 未压缩消息对应原记录；旧消息可以由明确覆盖范围的摘要替代 |
| 项目规则、初始记忆与后续更新 | 采用的有界快照、来源身份、版本及替代关系 | 初始快照位于固定位置，普通变化追加；重建时使用有效版本 |
| 按需读取的 Skill / MCP / 记忆 | 读取的来源快照及触发它的行为身份 | 在对应完整 Tool 组之后注入一次正文 |
| 成员任务和消息 | 独立的 agent_input 事实 | 只使用实际投递到当前 Session 的内容，不复制成员全部历史 |
| 压缩结果 | 摘要、覆盖范围、保留消息身份、采用的来源版本、已折叠更新边界 | 摘要替代被覆盖的历史，来源快照与后续增量分别恢复 |
| 状态、用量、审批等控制事实 | 原有控制与审计记录 | 按用途选择，不把整份日志机械转换成聊天消息 |

内部投影直接携带持久身份，不再依靠正文相等猜测关联。同样的两句“继续”仍是两条不同消息；来源文本与用户文本相同也不具备用户消息身份。固定规则和 tools 来自受控配置，不属于一次用户发言。

项目规则和记忆持久化为来源记录，不写成真实 user 消息。兼容现有 Model Adapter 时，可用明确标注来源的 user role 上下文块承载；传输 role 不等于会话发言者，更不等于授权依据。AutoAllow 继续只从真实用户消息及动作相关的人工批准取证。

来源快照可能先于对应 ToolResult 落盘，因此日志 seq 不能直接当作模型消息排列次序。投影必须关联实际 Tool 组，等完整组结束再注入来源；取消或恢复时的不完整组沿用既有终态处理，不能补造一次实际执行。

### 普通更新、压缩与恢复

假设初始采用记忆 M1，后续保存为 M2：

- 普通续聊保留已经发送的 M1 与历史，在末尾追加 M2 及替代关系；后续行动按 M2 处理。
- 压缩后采用有效来源快照 M2、覆盖旧历史的摘要、保留的完整消息与 Tool 组，再追加检查点之后的新内容。
- 原始历史仍保存曾经采用 M1 的事实；新视图不重放已被检查点折叠的旧更新，也不重复注入 M2。

压缩检查点必须能说明摘要覆盖哪些记录、保留哪些消息、使用哪些来源版本，以及哪些来源更新已经折叠。摘要主要保存任务经过、决定和未完成事项；项目规则和记忆的当前有效状态由独立来源视图表达，不能只依赖摘要记住层级和有效期。

只有候选摘要、来源版本和映射边界全部校验并成功持久化后，才切换模型投影。失败保留已提交状态；取消后不再发起模型请求。原始 Reasoning 继续只在当前 Run 内按现有合同临时续传，不因缓存目标新增持久化。

只读打开历史展示当时记录，不读取当前 memory/ 或工作区文件来重写过去，不要求 Workspace 仍存在，也不重新执行 Tool。用户明确继续时，先恢复已保存的检查点和来源，再核对当前规则、有效记忆与遗忘标记，把差异持久化后用于后续请求；必要时重建受影响视图。

普通回复、压缩和自动审批继续使用各自输入边界，不因为它们共用 Model Stream 就注入相同内容。

## 一致性、失败与模块边界

Agent 持有记忆读写、来源采纳、权限、取消和资源生命周期，通过少量查询与维护语义向 TUI 暴露能力。TUI 负责 /memory 的列表、详情、操作结果和状态呈现，不直接扫描目录或编排模型请求；内部持久身份、模型消息和 Provider 类型不扩张为公开接口。

/memory 默认显示当前项目与通用用户记忆，并允许按类别、范围和状态查看；详情可见正文、来源、适用条件、最后确认时间及有效状态。候选确认、纠正、遗忘和自动开关均返回明确结果；设置与内容操作失败不得显示成成功。

成员只读取任务相关的有界视图并提交带证据的候选，由根 Agent 校验和合并，不直接覆盖共享条目。不同根 Session 或进程写入同一存储也必须校验版本；成员、模型或外部来源不能通过记忆绕过用户授权。

| 情况 | 必须表现 |
| --- | --- |
| 尚无 memory/ 或没有匹配条目 | 按空记忆正常工作，不因只读查询创建空数据 |
| 个别记忆损坏、过期或条件不符 | 隔离受影响条目并显示原因，不静默作为可用内容；能够安全排除时允许继续 |
| 无法确认遗忘状态或无法移除受影响旧内容 | 暂停相关请求，不能沿用可能已经被撤销的来源 |
| 保存失败或写入中断 | 保留最后成功版本；返回失败，不能留下半份有效条目 |
| 记忆已保存，但 Session 来源增量保存失败 | 如实区分两步结果；停止使用未落盘的会话增量，下次按版本重新对齐，不重复制造条目 |
| 并发补充、用户纠正、遗忘和迟到候选冲突 | 不静默覆盖新版本；重新读取后处理，旧候选不能撤销已完成的纠正或遗忘 |
| 取消或退出发生在维护中 | 关闭所属资源，不继续隐藏模型调用；已经提交的写入保留，尚未提交的操作不能报告成功 |
| 源 Session 或产物被清理 | 独立记忆保留有效范围及必要说明，失效引用如实显示，不假称可以读取原文 |

Session 与记忆格式必须带版本并校验。旧 Session 保持可读，新增来源和检查点字段通过显式继续时的兼容路径接入；只读查看不破坏性迁移，也不把旧消息重新解释为用户授权。索引允许重建，不能成为唯一持久事实或替代遗忘标记。

## Agent Loop 次数限制调整

本 Spec 替代 [Feature 007 Spec](../feature007-multi-agent/spec.md) 默认预算中关于以下两项的约定：

- 单个 Run 最多 12 次普通模型请求。
- 根 Agent 与成员合计最多 60 次模型调用，包括普通回复、摘要和审批；没有成员的根任务也移除此截止。

累计次数可以继续用于观测，但不得单凭次数令任务失败、强制总结或终止，也不改成另一个更大的固定次数。

保留正常完成、用户停止、真实错误、权限约束、Tool 超时、上下文容量与压缩失败处理；保留 30 分钟共享任务时限、单批 32 个 ToolCall、只读并发 4、成员 3、消息队列和单次内容上限。压缩内部的分批与进度保护继续保留，它们不构成普通工作循环的次数替代限制。

旧 Session 中因既有限制停止的记录保持原事实。本次实现已同步运行合同、断言和现行文档；已完成 Feature 的历史报告保留当时事实。[归档调查](../../research/archive/2026-09-06-context-engineering/README.md)中的其他压缩设想继续搁置。

## 验收标准

以下按完整场景验收，可以复用同一组测试数据与验证链，不要求为每行机械增加独立单测。

| 编号 | 场景与通过条件 |
| --- | --- |
| A01 | 新会话自动加载正确项目根的 AGENTS.md 和适用记忆；缺失正常、读取失败可见；规则冲突与当前用户要求、权限边界分别正确处理 |
| A02 | 明确长期要求保存为用户记忆，已验证经验保留证据和条件，单次推断保持候选；/memory 与 Agent 查询看到同一份状态，关闭自动记忆后仍可显式维护 |
| A03 | Agent 与 Plan 模式均遵守受管维护边界；人工修改忙时有明确结果，取消无遗留工作；敏感值和记忆内的授权声明不能绕过既有保护 |
| A04 | 不同项目经验不串用，同仓库 worktree 能共享适用经验但各读自己的规则；非 Git 项目可用，分支及环境条件变化触发复核 |
| A05 | 用可控时间和条件变化证明临时要求到期退出、长期偏好保持、待复核内容不冒充已验证；重复读取不刷新最后确认时间 |
| A06 | M1 更新到 M2 后只追加有效变化；重复读取不重复注入正文，当前会话、压缩后及恢复后均正确采用 M2，历史仍保留 M1 的事实 |
| A07 | 遗忘后检索、旧摘要、重启恢复、其他会话和成员迟到候选均不能使其复活；要求停止发送的内容从后续投影移除，已经发出的请求与原始历史边界明确 |
| A08 | 不同根或进程并发更新，以及记忆保存、Session 追加中断时，不丢失已成功操作，不虚报成功；损坏条目和来源被清理有可解释结果 |
| A09 | 两条同文消息按持久身份区分；每个投影块可回查原消息、来源版本或摘要范围；来源落盘早于 ToolResult 时仍在完整 Tool 组后注入，不制造虚假调用或真实用户授权 |
| A10 | 压缩保存覆盖范围、保留身份、来源版本与折叠边界；失败不切换半成品视图；旧 Session 可只读打开，明确继续才协调新来源，不重放副作用 |
| A11 | 相同配置和工具集合下装配结果确定；新增 Skill / MCP 正文、检索结果及普通记忆更新保留此前前缀；真实工具、模型或权限变化按事实生效，必要重建有明确原因 |
| A12 | 缓存用量未知时不显示为零命中；可比较的 token 汇总口径正确，并记录记忆维护与总输入开销；本地前缀检查不被报告成已证明的真实缓存提升 |
| A13 | 有限的确定性任务超过 12 次普通请求、根单独超过 60 次总调用、根与成员合计超过 60 次总调用后，均可继续并正常结束；摘要与审批不触发共享次数截止 |
| A14 | 长任务中用户停止、模型失败、Tool 超时和 30 分钟时限仍按原原因终止，组取消能传播；解除次数限制没有留下停止后继续请求或未释放的资源 |

优先通过现有 Agent Interface、确定性 Model Stream、本地 OpenAI-compatible 服务和实际 TUI 行为覆盖这些场景。并发、损坏和取消只补必要的故障注入，不为本 Feature 另建测试框架或暴露内部循环步骤。

Plan 需给出定向验证命令和可重复场景。真实 Provider 缓存对照须单独授权；尚未运行时在 Report 保留未验证说明，不能用此前通过的基线测试声称本 Feature 已实现。

## 不在范围内

- 嵌套目录 AGENTS.md 继承、远程规则自动获取，以及 Agent 自动改写项目规则文件。
- 向量数据库、知识图谱、跨设备同步、多人账号系统、后台整理 Agent 或每轮额外的记忆总结调用。
- 将每条聊天消息保存为长期记忆，或把本 Feature 扩成完整个人知识库。
- 原始 Session、备份和产物的统一敏感信息擦除；现有会话清理功能保持自己的语义。
- 归档调查中的主动压缩调度、草稿到最终摘要、多轮摘要优化或新的模型上下文预算查询工具。
- Provider 专属缓存接口、模型专用分支、固定缓存命中率或费用承诺。
- 移除 30 分钟时限、并发和队列边界、Tool 资源限制或压缩内部保护。
- OS 沙箱、Desktop Adapter、专用工程验证平台，以及本 Spec 之外的新授权机制。
