## 实施顺序

1. **记忆管理闭环。** 增加版本化本地存储、范围与时效选择，接入 Agent 查询与维护和 /memory；通过临时工作区完成保存、查询、纠正、候选确认、遗忘与重开。
2. **主动记忆与项目规则。** 接入受管 memory Tool；来源必须绑定真实用户或已完成 Tool 证据，成员提交候选由根合并。装配应用记忆根、Git 项目身份和各工作树 AGENTS.md。
3. **来源与请求装配。** 将来源采用移到 Context，固定基础规则与初始快照，后续正文追加；稳定工具排序，保持读取结果与来源正文不重复。
4. **历史身份与压缩恢复。** 由内部持久身份关联消息和投影，扩展来源及检查点版本信息；完整 Tool 组后注入来源，先验证和保存再切换投影，覆盖只读旧历史和明确继续。
5. **长任务与一致性。** 去除 12/60 次截止，保留 30 分钟及其他资源限制；验证并发根、遗忘、取消、写入中断、过期与来源清理。
6. **完整验证与交付。** 定向场景通过后执行项目检查、构建与完整测试，审查 Spec 覆盖及权限/恢复风险，修复发现并形成 Report。

各增量是实施顺序，不另建交付 Stage；当前授权覆盖完整 Feature。

## 具体实现合同

- 本地文件使用带格式版本的 JSON 条目，每条有稳定身份、修订号、范围、来源、状态和确认时间；用户与项目经验分别存放。设置保存于 state，遗忘保留不含正文的必要抑制信息。
- 使用存储根级独占锁协调不同进程，条目以临时文件写入后替换。锁等待有界、可取消；死亡写锁持有者通过独占恢复锁协调恢复，恢复过程自身中断时保留诊断，不抢占可能正在恢复的进程。索引可重建，成功写入不能依赖仅在内存中的索引。
- 自动维护仅在正常 Run 内执行。明确用户要求可形成有效用户记忆；经验需绑定已完成的证据，推断和冲突保持候选。维护 Tool 无权声明额外用户授权，开关与角色由运行时核验。
- 初始用户摘要与经验索引分别以 8 KiB 为上限，单条正文 8 KiB；项目规则完整读取上限 64 KiB，全部活跃来源上限 128 KiB。数量过多时按确定顺序选择并显示省略，不能截断必要项目规则。存储扫描与单次返回有界。
- AGENTS.md 按 Git 工作树根或非 Git Workspace 定位；共同 Git 目录识别项目，不能把有 HEAD 当作记忆启用前提。文件条件复核只读取证据关联的有界本地内容，遵守工作区范围。
- 模型消息与持久记录的关联仅在 Agent 内部携带，不向 TUI 暴露模型协议。旧格式只读兼容，显式运行时才补入新版来源与检查点。
- 来源快照保留稳定身份、版本、初始位置以及触发它的 Tool 组。运行时撤销检查覆盖后续请求和未开始 Tool；无法安全移除的历史摘要不得继续发送。
- Agent Interface 以 memory 查询和维护语义接入；TUI 显示数据及操作结果，不管理存储、来源或模型生命周期。
- 采用现有用途分类与缓存用量统计，必要时修正来源移入消息后的预算计数；不引入模型专属缓存参数或额外后台总结调用。

## 验证

按增量运行受影响的定向测试与 pnpm exec tsc -p tsconfig.test.json --noEmit；同一版本已通过的测试不重复执行。重点覆盖 Spec A01–A14，优先复用 Agent Interface、确定性 Model Stream、本地 OpenAI-compatible 服务和现有 TUI seam。

最终执行 pnpm check、pnpm build、pnpm exec vitest run。多进程并发使用临时存储和有限子进程；长任务使用有限的确定性调用序列，可控时间验证 30 分钟时限。临时目录由测试持有并清理，不保留演示后台进程。

独立审查只补 Spec 遗漏、权限、并发与恢复的证据缺口，不重复执行已有可信测试。真实 Provider 缓存对照及主观终端体验在 Report 中明确证据边界。
