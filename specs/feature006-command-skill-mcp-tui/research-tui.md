## 1. 本轮已确认的方向

开发者希望下一 Feature 包含常用 `/` 命令、规范的外部 Skill 接入、MCP 接入，以及符合 Anthias 主题的 TUI；Skill 首期不自行生成，外部内容要延迟或按需加载。

在全屏与终端原生 scrollback 两种交互方向中，开发者明确选择：**全屏布局、固定面板与应用内滚动**。这调整了现有技术基线中“稳定 scrollback + 动态底部”的显示合同。当前实现事实仍在稳定文档中保留；新的全屏合同在后续 Spec 确认后再进入实施，不把研究建议写成已实现能力。

全屏只改变 TUI 对输入与画面的持有方式。Agent 仍然是模型、Tool、Session、权限和副作用的权威；TUI 可以持有滚动、输入缓冲、选区、菜单和详情焦点，不能取得业务执行权。

## 2. 源码事实：闪屏与跳动不是终端必然限制

### 每次刷新都擦掉整个动态区

`apps/tui/src/terminal-driver.ts`（调研基线 `4855892`，本 Feature 实现时已移除） 的 `renderDynamic()` 无条件调用 `clearDynamic()`。后者逐行写擦除、移动光标指令，随后 `renderDynamic()` 再写入所有行与光标状态。没有相同帧判断，没有变更行比较，也没有同步输出帧边界。`writeStable()` 也会先清动态区，再交由上层恢复。

[Terminal Conversation](../../apps/tui/src/terminal-conversation.ts) 把每个 AgentEvent 串行处理后立即刷新动态区，按键也会请求刷新；Reasoning 或 Tool 活跃时，另有 250 ms 计时刷新。事件顺序值得保留，但事件处理次数不应等同于物理绘制次数。当前慢速文件解析或代码高亮还会占住同一串行队列。

### 正文存在两个显示阶段

[Content Renderer](../../apps/tui/src/content-renderer.ts) 只把完整行与闭合代码块提交到正文。未完成文本由 `preview()` 返回，TUI 只展示最后四行预览。长代码块会先只显示尾部，闭合后才整块进入正文，因此即使减少擦除，仍会有内容突然展开和位移。

同一个 Renderer 对文件引用和 fenced code 有专门处理，但普通标题、粗体、强调、列表层级、普通行内代码和网页链接没有完整 Markdown 排版。当前“文字不好看”有格式支持不足的原因，不能只归因于配色。

### 本轮运行证据

Windows、Node.js `v24.13.1`。使用 Node 的 TypeScript 源码加载及仅映射内部 `.js` 导入的 hook，直接调用当前 `src`，输出写入内存 Writable；没有使用可能过期的 `dist`，没有连接 Provider 或运行工作区业务 Tool。

| 探针 | 实际结果 | 能证明什么 |
| --- | --- | --- |
| 同一五行 frame 连续呈现 | 第二次仍有 18 次 write、5 次整行擦除、174 字节，无同步输出标记 | 无变化也会清除和重写 |
| 五行 frame 只改第一行 | 18 次 write、5 次整行擦除，未变的 Workspace 也被写回 | 没有按变化行更新 |
| 开始代码块并输入八行代码 | 正文提交 0 字节，预览已有 9 行 | 代码块被缓存到闭合 |
| 闭合同一代码块 | 一次提交 10 行，预览清空 | 完整代码在闭合时集中出现 |
| 标题、粗体、普通行内代码、网页链接 | 原始 Markdown 标记均保留 | 这些常见格式未被转换呈现 |

以上证明源码的输出行为与用户描述相符，支持其为闪屏和跳动的重要原因；没有测量真实显示器帧率，也没有凭内存字节流宣称完成 Windows Terminal 的主观视觉复现或修复。

## 3. 官方参考与技术取舍

本地 pi 是 `581d75a89cea21e50d6a26df840352f94427f633` 快照，其中 `@earendil-works/pi-tui` 为 `0.84.1`；本地跟踪状态落后 upstream，不能叫最新发布版本。在线另核对了当日官方文档。

pi 的独立 TUI 包已有 `TuiMainScreen` 与 `TuiAltScreen`；后者使用固定高度视口、可独立滚动区域和布局组件，并有 Markdown、Editor、补全与 Overlay。差量更新和同步输出用于减少中间画面；它并不要求引用 pi 的 Agent 或 Session 业务。[pi TUI 官方说明](https://github.com/earendil-works/pi/blob/main/packages/tui/README.md)

本地源码对应 `[firstChanged, lastChanged]` 的变更范围和成对的 `CSI ?2026 h/l` 帧标记。全屏模式另持有滚动状态与视口缓存。其包要求 Node `>=22.19.0`，运行依赖包含 `marked` 与 `get-east-asian-width`，并有 Windows/macOS 的原生辅助文件；因此与 Anthias 的 Node 24 方向相容，但还要核对发布包、原生回退与实际平台行为。[包定义](https://github.com/earendil-works/pi/blob/581d75a89cea21e50d6a26df840352f94427f633/packages/tui/package.json)、[主屏源码](https://github.com/earendil-works/pi/blob/581d75a89cea21e50d6a26df840352f94427f633/packages/tui/src/tui-main-screen.ts)、[全屏源码](https://github.com/earendil-works/pi/blob/581d75a89cea21e50d6a26df840352f94427f633/packages/tui/src/tui-alt-screen.ts)

Windows Terminal 的官方 `v1.23.20211.0` 发布说明已经列出 DECSET 2026 支持回移；不能沿用旧资料宣称 Windows Terminal 完全不支持同步输出。但这不证明开发者当前运行的终端版本或所有终端都支持。应检测或保守降级，并保持单批输出和差量更新；一次 `write` 也不等于所有终端必然原子显示。[Windows Terminal 发布说明](https://github.com/microsoft/terminal/releases/tag/v1.23.20211.0)、[同步输出说明](https://contour-terminal.org/vt-extensions/synchronized-output/)

| 选择 | 收益 | 需要承担的成本 | 本轮建议 |
| --- | --- | --- | --- |
| 复用 pi 独立 TUI 包 | 已有全屏、Editor、Markdown、滚动与补全 | 发布版本、中文输入、复制、退出行为及安全文本接入需要验证 | 优先做兼容性验证，验证后再锁定依赖 |
| 继续扩展当前 Driver | 完全掌握代码与依赖 | 需要自行实现布局、视口、选区、输入、差量缓存与终端协议 | 保留为验证不通过后的选择 |
| OpenTUI | 提供完整终端布局与渲染能力 | 官方开发与接入路线以 Bun 为主，额外改变当前运行时选择 | 本轮不建议为 TUI 同时迁移运行时 |

OpenTUI 路线依据其[官方仓库](https://github.com/anomalyco/opentui)。以上是选择建议；本轮没有安装依赖、改用 Bun 或复用外部 Agent 生命周期。

## 4. 建议的全屏体验

### 稳定区域

- 顶部显示小型鱼形标识、Anthias 与完整 Workspace；品牌色集中用于标识、焦点和关键状态。
- 主对话区占据最大面积，支持应用内滚动；User、Assistant、Reasoning、Tool 的层级靠留白、短标签和有限语义色表达。
- 底部输入区和状态区位置稳定，输入支持多行、历史和括号粘贴；长粘贴不能被拆成多条 prompt 自动发送。
- Tool、Reasoning、Skill、MCP 和上下文详情使用一个可展开的详情区域。宽屏可放右侧，窄屏变为覆盖面板，关闭后回到原输入和滚动位置；不同时铺满多个侧栏。
- `/` 打开就近候选菜单，支持筛选、补全、键盘选择和参数说明。未知命令本地报错，不发送给模型；普通文本中的 `/` 不被劫持。

主正文使用清晰的默认前景色。沿用 Anthias 的珊瑚色、紫色和 Lagoon 点缀，避免把整个回复染色或给每个段落加边框。亮色、暗色、无颜色与 ASCII 都需要可读。

### 流式正文与历史阅读

1. 当前 Assistant 消息在同一正文位置增长。Markdown 支持标题、粗体、强调、行内代码、列表、引用、链接、表格和代码块；窄屏表格允许明确降级。
2. 未闭合代码块仍显示已经收到的代码。高亮可以稍后补齐，但不能等完整代码块才展示，也不能让高亮失败中断输入或后续事件。
3. 只更新可见区域中变化的行；多个快速 delta 可以合并成一次绘制，所有事件事实仍按顺序处理。相同可见帧不写出，计时刷新不反复擦正文。
4. 位于底部时跟随新回复；向上滚动后固定阅读锚点，并提示有新内容；回到末尾才恢复跟随。resize 后尽量保留正在阅读的消息位置。
5. 代码和回复能明确复制，选中文本时不能误触停止运行。应用内鼠标选择、终端原生选择的修饰键方式，以及不同终端的剪贴板限制必须实际验证。
6. 长会话只对需要的内容做布局和呈现，避免每个 token 都重新解析全部历史。视口缓存不能变成第二份 Session 权威。

### 运行、审批与退出

运行中的输入可编辑并保留草稿，提交策略先沿用当前“不并发开始另一个 prompt”；不在本轮顺带加入 steering 或队列协议。Esc 优先关闭菜单或详情；停止与退出继续映射 Agent 的取消和关闭，不由界面伪造终态。

审批发生时，目标、动作、权限模式和后果必须在同一可审阅区域看到；长内容可滚动，不能只留下确认按钮。窄到无法安全阅读时暂停确认并给出恢复路径。

正常退出、异常和取消都要恢复 alternate screen、光标、raw mode、鼠标与粘贴模式，并释放计时器和监听。回到 Shell 后建议显示简短会话恢复入口，不照搬 pi 退出时打印整个历史的产品选择。非 TTY 继续使用确定性纯文本，不发送全屏控制序列。

## 5. 与命令、Skill、MCP 一起形成闭环

命令候选优先是 `/help`、`/new`、`/resume`、`/context`、`/compact`、`/mode`、`/skills`、`/skill:name`、`/mcp`、`/details`、`/exit`。全屏下暂不建议加入语义模糊的 `/clear`；创建新 Session 已有 `/new`，视图动作可以在确定实际需要后添加。

这里有两类不同改动：帮助、菜单和折叠属于 TUI；新会话、恢复、手动压缩和外部能力属于 Agent 行为。当前 Agent 公共入口没有交互式新建/恢复/手动压缩，不能只加几个字符串分支就声称命令系统完成。

Skill 目录、已激活正文和 MCP 工具 schema 都需要进入 Feature 005 的上下文预算。外部 Skill 引用与 MCP 结果也不能成为 AutoAllow 的用户授权来源。MCP Tool 的动态身份、权限、取消、大结果产物和失败隔离必须接入现有真实执行链。

只读命令可以在 Run 中打开查看。改变 Session、Skill 集合、MCP 工具定义的操作先限制在空闲执行，避免模型已收到的工具 schema 与实际可调用集合在一个 Run 中静默变化。

## 6. 建议的交付顺序与验收

这四个主题会改变输入、呈现、上下文来源和外部副作用，适合一个 Feature 下几个能独立验收的 Plan，而不是一次堆完后才看画面。

| 建议增量 | 能独立检查的用户结果 | 核心验证 |
| --- | --- | --- |
| 全屏 TUI 与统一命令入口 | 使用现有 Agent 稳定读写对话，打开帮助、模式、上下文和详情；先解决闪屏与流式排版 | 本地确定性流、重复帧、未闭合代码、滚动锚点、多行输入、resize、Windows Terminal 主观验收 |
| 会话命令与外部 Skills | 新建/恢复 Session，手动压缩，发现并调用外部 Skill | 当前 Session 失败保护、按需加载、目录冲突、引用边界、压缩后可继续、无权限提升 |
| MCP 接入与统一体验 | 配置并启用服务器，从 TUI 看见能力状态，按需调用并取消、退出 | 两种传输与选定版本、schema 预算、审批、断连、结果截断、未知副作用不盲目重试、进程清理 |

这是交付讨论顺序，不是已经确认的 Plan；若 Skill 与会话命令单阶段过大，可按实际验收价值拆开。MCP 是否同批包含 Resources/Prompts、是否兼容旧协议、OAuth 是否延期，见配套调查的待决定点。

TUI 的验收不能只用测试数量代替。至少要直接观察：连续长回复不中途擦白、代码不整块突现、向上阅读不被拖回底部、中文输入与粘贴可用、停止后仍能输入、审批依据完整、退出后 Shell 正常。真实 Provider 验证另按本 Feature 的具体必要性授权；本次 Research 不继承 Feature 005 的调用额度。

## 7. 本轮证据边界

本轮修改仅包括 Feature 005 验收文档、Feature 006 的两份 Research，以及对话中的全屏布局示意。示意使用明确的示例内容，用于查看布局、详情、命令菜单和续写时的滚动关系，不证明终端渲染性能。隔离浏览器已检查命令筛选、Skill 详情、渐进续写、上滚后位置保持、返回末尾，以及 360 px 窄屏布局；全部通过，没有脚本错误。预览服务与浏览器已关闭。

未修改应用源码、依赖或 lockfile；未启动真实 MCP Server、安装外部 Skill、读取凭据、调用真实模型、提交、推送或创建 PR。已有可信 Feature 005 测试没有重复运行；本轮只补了当前 Renderer 的诊断探针与文档/示意检查。
