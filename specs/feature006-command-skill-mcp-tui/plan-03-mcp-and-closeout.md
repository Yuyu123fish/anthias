# Feature 006 Plan 03：MCP 接入与整体收口

状态：已实现，待开发者验收

## 开发者速览

> **一句话**：让用户显式接入 MCP 并通过现有 Agent 安全使用其能力。<br>
> **核心做法**：官方客户端处理传输，Tool 与 Context 承担执行、权限、预算和持久事实。<br>
> **边界**：本地协议夹具验证两种传输，不连接开发者真实服务或读取凭据。<br>
> **风险 / 未验证**：本地两种传输及 stdio 新旧版本协商通过；HTTP 旧版本与真实服务互操作未验证。<br>
> **当前 / 请审阅**：MCP、整体检查、有界审查和文档均已完成，证据见 [Report](report.md)。

对应 [Spec](spec.md) 与 [Tasks](tasks.md)。依赖 `@modelcontextprotocol/client@2.0.0`；协议支持按实际包和夹具结果记录，不把研究结论替代运行证据。

1. MCP 执行 Agent 负责 `mcp/`：安全配置、显式连接、能力目录、调用/资源/模板、取消、超时和关闭；通过本地 stdio/HTTP 实际协议夹具验证。
2. 根 Agent 扩展 Tool 定义和执行计划，绑定 server/tool 身份与连接版本，校验输入，复用审批、大输出与失败语义。
3. 接入手动资源/模板的有来源上下文及 TUI 详情；配置本身不得自动启动项目命令或发起外连。
4. 汇总静态检查、构建、各 Agent 独立结果与剩余集成回归，补编译后 CLI 的本地端到端证据；完成一次有界审查，修复实际问题。
5. 完成唯一 Report、Tasks 与稳定文档的实现事实。最终状态为已实现，开发者主观终端和外部服务验收单独说明。

MCP 执行者运行 `pnpm exec vitest run apps/agent/test/mcp.test.ts`；根 Agent 不重跑其同版本结果，只补 Tool/权限/Agent 和 CLI 集成。最后运行 `pnpm check`、`pnpm build`，按已运行文件清单执行尚未验证或已变化的用例，形成全套覆盖记录。

配置歧义、unsupported schema/内容、连接失败均有安全诊断；不盲目重试未知副作用。退出必须收口客户端和本轮启动的进程。不提交、推送或创建 PR。
