# Feature 010 后续增量

状态：已实现

## 开发者速览

> **一句话**：减少重复动作确认，补强任务持续执行，并在暂时失败或输出截断后自动恢复。<br>
> **核心做法**：新调用重新审核；失败响应先保存，重试与续跑共用有界预算。<br>
> **边界**：延续现有 Agent、权限和 Session，不增加 OS 沙箱或新 Feature。<br>
> **风险 / 未验证**：真实模型减少追问的效果、Provider 恢复兼容性及人工终端体验未实测。<br>
> **当前 / 请审阅**：实现和本地验证完成，开发者已授权补文档并做一次本地提交。

本文记录带日期的后续调整，不改变 Feature 验收状态。当前能力与验证边界见 [Report](report.md) 和[技术基线](../../docs/technical-baseline.md)。

## 2026-09-09：重复确认与有界自动恢复

### 问题与范围

实现基线为 `main @ c1dc459`。开发者明确要求直接实现三个增量，无需新写 Spec；本次继续修复 Feature 010 已涉及的审批、模型续轮和 TUI 失败呈现，不新建 Feature 或 Stage。

用户提供的成员会话及其根会话不能证明 AutoAllow 弹窗故障：该样本使用 Full Access，29 次授权均由策略直接允许，没有人工审批；两个 Run 正常结束，也没有手动 `/continue`。其中追加“要不要继续调整”的文字属于主模型行为，需要与运行时审批分开处理。

另外通过本地确定性模型复现了真正的重复动作问题：同一 Run 中两次输入相同、ToolCall ID 不同的命令，首次审核通过后，第二次被“本 Run 已审核同一动作”规则直接转成人工。因此改动分别落在授权判断、持续执行提示词和技术故障恢复三处。

### 改动后的行为

**新调用重新审核。** 移除已审核 fingerprint 必须转人工的规则。匹配有效工作区授权的调用继续直接采用授权；其他新调用重新接受审核。审核输入增加本 Run 中同一动作的实际开始次数及最近结果，已开始但结果未知也占一次，过去的 allow 不成为无限次授权。用户拒绝、授权撤销、固定安全策略和执行前权限版本复核继续生效。

**持续完成已授权工作。** 主提示词要求完成必要修改、验证和修正；普通实现细节自行判断，仍有必要工作就继续调用工具。只有缺少关键输入、新授权或无法自行解决的阻塞才提问，完成后直接报告结果，不默认追加是否继续优化。不增加完成审核模型，也不按回答中的关键词强制续跑；行为效果仍取决于模型遵守提示词。

**审核技术故障单独恢复。** 网络、限流、服务故障、输出截断或格式异常最多恢复一次。有效的 `needs_user`、`deny` 沿用人工决策流程，不为获取 allow 而重试；认证、配置和无效请求直接失败。技术故障耗尽后 Run 失败并显示审核故障来源，不转成人工批准。每个实际请求记录一次已知或未知用量，用量存储失败立即停止。

**普通生成有界恢复。** 未交付内容时继续使用原请求重试；已交付文本、Reasoning、工具参数片段或完整 ToolCall 后遇到暂时故障，先保存失败 AssistantMessage，为未执行的完整调用补齐 aborted 结果，再基于实际历史发起新生成。输出达到上限时同样续跑，并提示按文件或完整片段缩小输出。

原请求重试与新生成续跑对同一条未完成生成共用最多两次恢复机会。正常完成后，下一工具轮的生成可以使用新预算；整个任务仍受原 30 分钟共享时限约束。等待遵守 Retry-After，超过 30 秒或剩余时间不足时停止。自动恢复不新建 Run、不伪造 UserMessage、不新增授权，也不重置取消信号、拒绝记录或任务截止。

已经完成的 Tool 副作用不自动重放；结果不明时先检查。认证、配置、无效请求、内容过滤、存储失败和用户停止不触发普通续跑；上下文溢出沿用已有有界压缩。并发批次发生审核故障时，先收齐其他 worker 的真实结果，再为未执行调用收尾，避免把已经发生的结果丢失或写成未执行。

**TUI 呈现。** 区分“模型重试”“任务续跑”和“审核恢复”，分别展示预算与取消提示。恢复过程中不提供手动 `/continue` 提示，最终停止后才展示继续入口；审核故障保留来源说明。

### 实现与兼容边界

- `session-agent.ts` 持有授权和执行前复核，`permission/auto-review.ts` 依据真实用户来源及当前 Run 的执行记录判断。
- `agent-loop.ts` 先持久化失败响应和工具配对，再组织新生成；`context/index.ts` 与 `model-retry.ts` 沿用同一生成的恢复计数。
- 续跑提示只进入当前请求的系统上下文。失败 Reasoning 不写入历史，不将其残片拼接进下一次生成。
- Agent 的操作入口保持原样；既有 `model_retry` 事件增加可选 `recoveryKind`，供 TUI 区分恢复来源。
- Session 仍为 Schema 3，没有新增持久字段或数据迁移。校验允许失败 AssistantMessage 保存后，在恢复等待期间以 aborted 结束 Run。旧版校验器可能拒绝这一新顺序，不承诺向旧版本降级读取；未决 ToolCall 仍必须先配对。
- Full Access、工作区授权范围和系统用户执行身份不因本增量扩大；没有安装或实现 OS 沙箱。
