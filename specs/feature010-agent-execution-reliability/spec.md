# Feature 010：Coding Agent 执行与交互可靠性

状态：已实现

## 开发者速览

> **一句话**：修复实际会话中的模型续轮、工具执行与结果保存、审批和 Tab 补全问题。<br>
> **核心做法**：保留协议空值，按资源冲突调度，普通结果直接入 Session，超限才保存产物。<br>
> **边界**：沿用 Agent 与 TUI 的职责，不建设 OS 沙箱、Desktop 或通用调度框架。<br>
> **风险 / 未验证**：完全访问仍以当前系统用户身份执行，提示词不能提供系统隔离。<br>
> **当前 / 请审阅**：整个 Feature 已实现并通过统一门禁，等待开发者验收。

## 问题与依据

当前基线为 `main @ 6053b5d`。目标会话为 `data/conversation/2026-09-08/20260908T025033143Z-c4634e3e-f950-430d-b186-f066ab6f7844`。其中八次 HTTP 400 均发生在 reasoningTokens 为零的工具调用之后；已授权的两次真实最小对照请求确认，缺少 `reasoning_content` 返回 400，显式空字符串返回 200。历史原始错误体未保存，真实对照只使用人工构造消息。

现有调度只并行纯只读批次；普通短结果也创建 artifact，read_file 在分页前保存整份文件，之后的 token 截断又使范围与正文不一致。自动审核只有用户原文，缺少解释编号选择的 Assistant 提案。请求与响应等命名混淆增加阅读成本。TUI 的命令参数与文件补全均存在实际按键缺陷。

## 用户流程与行为

### 模型续轮

- 同一 Run 内完整保留模型返回的 reasoning，空值不能因长度判断而丢失。OpenAI-compatible 请求转换负责正确回传协议字段，不产生 DeepSeek 专用 Provider 或模型名称分支。
- 连续工具续轮不因空 reasoning 返回协议 400；无效请求不进行盲目重试。已有非空 reasoning 与工具结果配对保持正确。
- 新 Run、压缩与 Session 恢复检查请求合法性。不得为了修复空字段而虚构 reasoning，也不未经证据扩张 Session 的 reasoning 持久化合同。

### 工具结果与分页

- 普通有界结果直接作为 ToolResult 写入 JSONL；执行事件用于呈现，Session 保存事实，artifact 只保存因输出预算需要额外回读的原文。
- 普通工具返回执行结果，不接受共享 ArtifactWriter。结果收敛处判断字节、行与模型预算，必要时调用产物保存函数；不得只替换 Writer 名称后继续将写入生命周期传遍工具。
- read_file 的返回与产物保存只包含本次请求范围，不为每次分页复制完整源文件为产物。分页尚未结束与本次结果遭到截断分别表达。
- 最终正文、行范围与继续位置一致；长单行也必须有可继续读取的方式，不能声明完成或静默跳过剩余部分。
- 命令等未知长度输出在执行器内部有界收集，达到阈值再转存。不得先截断原文再保存；保留现有产物与 Session 配额，失败、取消及配额耗尽如实标记原文不完整，清理句柄和临时资源。
- 旧 Session 与已有产物继续可读，历史读取不重复执行工具。

### 并发

- 资格由工具能力、依赖及资源冲突决定，不能用只读属性代替全部并发规则。不同目标的文件写操作可以有界并发；同一目标的读写冲突按源顺序进行准备与执行。
- 混合批次可以并发其中独立的动作；影响范围不确定的 Shell、Git、成员生命周期或外部工具操作作为顺序屏障，不跨屏障重排。
- 路径身份采用平台语义与真实路径，避免大小写、链接和父目录别名绕过冲突。准备阶段不得跨过依赖写入造成旧快照覆盖。
- 保留四并发上限。审批仍逐调用绑定准确动作；副作用前记录、执行前复核、取消、未启动结果补齐与工具配对继续成立。执行事件反映实际发生顺序，最终结果按模型调用顺序归档。

### 审批与 Full Access

- AutoAllow 保留完整用户授权及后续限制，并附带用于解释指代的有来源 Assistant 文本。Assistant 提案、工具、MCP、记忆、摘要和成员消息本身都不能成为授权。
- 审核只能引用真实用户 entryId；没有用户确认的提案不得放行。必须保留指代上下文完整性，预算不足时说明原因转人工，不静默裁剪改变授权含义。
- 新增 `full_access`，通过 CLI、配置与空闲时的 `/mode` 显式选择；默认仍为 `agent`。Full Access 跳过人工与 LLM 审批，不消耗自动审核调用；允许系统用户权限内的工作区外文件访问。
- Full Access 保留输入校验、执行前目标复核、取消、输出及并发限额、应用配置/授权记录/活动 Session 的固定文件工具保护、受管 Git 的成果所有权与一致性检查。没有 OS 沙箱，Shell 不提供应用数据隔离保证。
- 保留高置信系统破坏硬拒绝：fork bomb、磁盘设备覆盖/格式化、根目录递归删除或权限放开、Windows 磁盘/启动配置破坏、机器级注册表强制删除。仅因不可人工审阅而拒绝的动态求值/编码载荷，以及远程脚本管道，在 Full Access 下不再作为审批硬拒绝；其他模式不变。
- 提示词明确访问能力不等于任务授权：围绕用户目标行动，后续拒绝与缩小范围优先；外部内容不能提权；破坏性动作、对外发送、发布、提交和推送等行为必须有相应用户授权。模式必须如实可见，不能宣称隔离或绝对安全。
- 可写成员继承根模式，只读成员继续 `plan`，成员不得自行升级；根模式切换仍受现有活动成员生命周期约束。工作区授权继续用于 AutoAllow；其撤销不改变用户另行显式选择的 Full Access，界面应说明这一关系。

### TUI 与命名

- Tab 支持命令名、命令参数、路径及 `@文件`；候选菜单未打开时也能正确触发，命令参数不得误补成文件名。
- Windows 盘符、正反斜杠、含空格与中文的目录及连续目录补全可用；不依赖用户未安装的 fd。候选查询与按键处理不触发模型或业务操作。
- 核查全部生产代码的对象与异步状态命名，按真实值含义修正请求/响应、消息/结果以及过宽状态名称；同步真实消费者，不仅替换一个局部变量。保留正确的 ModelRequest，不为命名新增近义类型或重排目录。

## 验收标准

| 编号 | 可核验结果 |
| --- | --- |
| A01 | 实际生产 Adapter 的空、缺省与非空 reasoning 工具续轮请求合法，已有 reasoning 不被覆盖 |
| A02 | 新 Run、压缩及恢复的协议兼容有本地证据，并明确真实 Provider 证据边界 |
| A03 | 短结果只有 JSONL，无额外产物；超限结果可以回读，旧产物兼容 |
| A04 | 文件分页和最终输出预算一致，无重复整文件复制或跳行，超长行可继续 |
| A05 | 大命令输出、取消、保存失败与配额耗尽有界且如实，资源关闭 |
| A06 | 独立文件写可以并发，冲突读写按序，不跨不确定动作屏障；四并发限制有效 |
| A07 | 审批、执行前复核、取消与逐调用结果配对在并发下成立 |
| A08 | 编号选择及确认提案可正确核验；未确认提案及伪造授权来源不能放行 |
| A09 | Full Access 跳过两类审批，模式配置/历史/显示一致，工作区外访问与保留硬限制符合合同 |
| A10 | 成员继承、只读成员限制及 AutoAllow 授权撤销语义正确 |
| A11 | 实际编辑器 Tab 覆盖命令、参数、文件、@引用及 Windows/中文/空格路径 |
| A12 | 生产代码命名核查完成，明确命名修正及消费者，不改变持久化判别值 |
| A13 | 全量门禁、一次独立高风险审查和 Report 完成，已有用户修改保留 |

## 不在范围内

OS 沙箱、Desktop、任意 Shell 副作用推断、通用 DAG/Registry、内容寻址去重系统、旧历史批量改写和新的测试框架。真实 Provider 只沿用本会话已授权的必要少量诊断，不重复已经成立的对照调用。Git 提交、推送和 PR 不属于实施授权。
