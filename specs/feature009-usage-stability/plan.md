## 基线与范围

依据 [Spec](spec.md)，基线为 `main @ cd3ac87`。开始时只有本 Feature Spec 未跟踪，没有业务代码修改；Node 24.13.1、pnpm 10.33.0 可用。复用该 HEAD 已有的 Feature 008 验证结果与本次确定性诊断，不重复运行未改代码的全量基线。

本 Plan 覆盖 A01–A18 的代码与可执行本地验证，维护一个 [Tasks](tasks.md)。真实模型与 SearchAPI 不在本次调用授权内；历史页面使用测试副本核对客观布局，原文件不改写。真实人工终端体验和审美验收不能由自动结果替代。

## 实施步骤

1. 生产启动从 Anthias 根加载并安全创建无密钥 `.env`，环境值优先；提供 `.env-example`，显式 CLI 模式覆盖默认配置。增加 SearchAPI 内建只读工具，通过现有内部扩展接入根与成员，HTTP 取消、大小和安全错误在工具内部持有。
2. 增加 Agent 持有的工作区授权记录与语义入口。记录绑定规范工作区，区分会话与记住、是否包含登记成员 worktree；文件按最终路径匹配，命令按明确列出的字面入口、参数与 cwd 匹配，不解析得出的命令转 AutoAllow。授权位于应用数据中，和模型可写记忆分开。
3. 在原有预检、审核、开始记录与执行前复核之间接入授权。硬禁止和 plan 不变，auto_allow 才消费授权；根与成员共享当前授权修订，撤销即时使未开始动作和待审批失效，旧批准不能重新放行。持久失败明确区分当前进程与跨启动效果。
4. Model Adapter 输出安全错误分类与工具参数生成阶段；普通生成仅在无可见内容且无完整 ToolCall 时对暂时错误最多额外重试两次。Agent Loop 发布阶段，Session 保存有界原因、usage 和尝试事实；重试不扩展到压缩、审核或工具，不重置任务时限。
5. TUI 修复命令输出顺序、拒绝草稿恢复、滚动焦点及长结果详情；工具准备、等待、执行和失败完整可见，增加授权查看/授予/撤销与失败继续入口。所有业务状态继续来自 Agent。
6. 在 Coding 系统规则补齐按任务选择验证和如实交付的行为，修正已发现的工具说明歧义；用本地 TUI 场景与页面副本核对回归，不加入专用验证框架。
7. 合并后运行统一质量门禁并做一次独立高风险审查；修复明确问题，编写 Report 和更新 Tasks，区分已实现、本地验证与待开发者验收。

## 接口与所有权

- Agent 的 `permissions` 提供快照、授予与撤销，TUI 不直接访问记录文件。根创建的受管成员使用同一授权持有者，并显式标注自己的 workspace 与来源；切换会话时重新绑定当前工作区。
- 根目录配置继续在生产 Agent 工厂装配，不向 TUI 暴露 Provider 或 Model Stream。内建搜索通过 `AgentToolExtension` 接入，不增加 package 或 Registry。
- 新增 Tool 输入阶段、模型重试及安全失败元数据以有序事件传递；Session 兼容旧记录缺字段的未知状态。公开返回值只携带交互所需的安全事实。
- 各执行者只改分配文件；公共 Agent 入口、SessionAgent、权限与成员接线由统筹负责。TUI、模型恢复、配置搜索分别完成自己的定向验证，统筹统一运行最终全量。
