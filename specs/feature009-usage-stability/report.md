## 已交付行为

- **一次配置**：生产启动固定读取 Anthias 根 `.env`，首次缺文件时生成无密钥模板，不覆盖已有文件。仓库提供 [.env.example](../../.env.example)，本地 `.env` 已生成且被 Git 忽略。进程环境值优先，包含显式空字符串；权限模式依次采用显式 CLI、进程环境、根配置、`agent`。从任务目录启动不会读取该项目的同名模型配置。
- **网页搜索**：Agent 内建 `web_search`，根与成员使用同一装配方式，plan 可用。SearchAPI Google 请求返回有来源的标题、链接与摘要，支持分页；未配置搜索不会阻塞其他功能。凭据通过 Header 发送，固定服务端点，查询、响应、结果和等待均有界；本次只做本地 HTTP 验证。
- **减少重复批准**：`auto_allow` 消费显式工作区授权，覆盖普通工作区文件创建/编辑、17 项默认检查命令以及用户登记的精确命令或字面参数前缀。可仅本次使用或记住，可选择包含登记的成员 worktree；查看、授予和撤销均经 Agent 语义入口。命令未命中已确认的参数范围和确切 cwd 时继续审核，不因工作目录相同直接放行。
- **TUI 顺序与输入**：命令结果插入发生时的位置，后续 Assistant 进度继续显示在其后；长结果使用摘要和详情。被拒绝输入保留为草稿，异步返回不覆盖后来输入，`/draft` 可取回保存内容。焦点、滚动及首次打开详情的定位已做回归。
- **工具全过程**：参数准备、已收到调用、等待批准、执行和结果共用稳定卡片；并发及成员动作可以区分，失败默认显示具体原因。成员失败只结束对应成员的未完成卡片，避免残留“准备中”或误结束根任务。
- **停止原因与继续**：结束分类、Provider finish reason、可用 usage、重试次数和中止来源写入安全诊断。`/diagnostics` 查看事实，`/continue` 或后续输入开始新 Run；不自动重放已执行工具。无有效内容、输出截止、未完成 Tool 输入和存储失败不会被标作正常完成。
- **有限恢复**：普通模型生成尚未交付正文、Reasoning、参数片段或完整 ToolCall 时，暂时网络、限流及可重试服务错误最多额外重试两次。TUI 显示等待和次数，停止能取消后续请求；压缩、审核和 Tool 执行不加入这套重试。
- **实际交付**：Coding 规则要求按任务选择有效验证、如实描述结果；页面任务在具备浏览器能力时检查渲染、控制台、主要交互和窄屏。工具说明明确 `grep.path` 的目录语义、`edit_file.replacements` 格式及命令相对 cwd，失败校验继续保留。

既有 12 / 60 次模型调用截止继续保持移除。30 分钟共享任务时限、单批 32 个 ToolCall、4 个只读并发、最多 3 个成员，以及模型上下文能力与超时保留；普通输出默认预算的后续调整见下文。

操作示例见 [Quick Start](../../quick-start.md)。减少日常批准的典型流程是设置 `ANTHIAS_PERMISSION_MODE=auto_allow`，在 TUI 执行 `/permissions grant --remember`，浏览范围后输入 `grant`；需要成员继承时显式增加 `--members`。`/permissions revoke` 可在运行中撤销。模式选择与单次批准本身不会生成工作区授权。

## 入口与职责

| 调用链 | 职责 |
| --- | --- |
| TUI main → `startup.ts` → `local-config.ts` | 生产根目录配置装配、安全提示和默认权限模式；TUI 不构造 Provider |
| `startup.ts` → `web-search.ts` → 根/成员 managed Tools | SearchAPI 请求、取消、大小约束、来源和安全错误 |
| TUI `/permissions` → `Agent.permissions` → `workspace-permissions.ts` | 用户选择、独立授权记录、工作区与成员范围、撤销修订 |
| `session-agent.ts` → Tool 预检/授权 → 执行前复核 | 硬禁止优先；当前授权、重复拒绝和撤销在副作用开始前生效 |
| OpenAI-compatible Adapter → `model-retry.ts` / Context → Agent Loop | 安全错误、有限尝试、上下文恢复及有序阶段事件 |
| SessionAgent → Session → `diagnostic-view.ts` | 新 Run 事实持久化、旧记录兼容、TUI 结束原因与继续入口 |

没有新增 package、外部依赖、Host、协议层或通用权限/验证平台。配置与授权分别由生产装配和 Agent 持有，TUI 只持有交互状态。

## 授权、失败与资源边界

工作区授权保存到 Anthias `data/permissions`，不从 Session、记忆、AGENTS.md 或外部内容提取。只有 `auto_allow` 使用授权；`agent` 继续逐动作处理，`plan` 继续禁止普通写操作。命令按已确认的精确或前缀参数范围及 cwd 匹配，组合命令逐段检查；未登记入口、重定向、动态展开和不确定语法转审核。解释器前缀与构建脚本均可产生工作区之外的副作用，不构成 OS 隔离。

根与受管成员共用当前授权持有者。撤销首先改变本进程的有效状态，再持久化；尚未开始动作及旧待批准请求失效，旧用户批准不能重新恢复放行。已开始动作不宣称已撤回。保存失败保留并报告当前本地决定和跨启动限制。持久文件的新修订在后续检查时重新读取，不宣称提供分布式事务或对已运行命令的回滚。

授权存储、Session 保留区域及生产根 `.env` 对固定文件工具受保护，真实路径别名和配置文件硬链接也不能绕过读取/写入校验；Shell 的系统用户能力不因此变成沙箱。测试只使用合成凭据，没有读取或写入开发者真实 Key。

普通重试采用 500ms / 1000ms 基础退避，尊重可用服务端等待；等待超过 30 秒或剩余任务时间不足时停止。重试次数在一次上下文溢出压缩恢复之间共享，不重置任务时限；每次实际 Provider 尝试的可用 usage 只统计一次，未知 usage 保留未知。只出现准备阶段可以重试，已经收到参数内容或完整 ToolCall 则不自动重试。

诊断只保存受控分类、固定摘要、允许的结束原因、错误码及标准参数路径和数字字段，不持久化任意异常正文、堆栈或原始响应。正常结束的记录若保存失败，当前状态与终态事件改为 `storage` 失败，不继续显示“模型已正常结束”。新增元数据可选，旧记录缺失项显示未知；查看历史不触发执行。

继续以持久消息和 Tool 结果作为下一次模型请求的事实，不自动恢复旧批准或重放副作用。本地回归已证明指定失败后继续不会重复成功写入及批准；这不等同于对模型未来选择的所有操作作出“恰好一次”保证。
