# Feature 009：日常使用稳定性与交互体验

状态：已实现

## 开发者速览

> **一句话**：让日常 Coding 任务少被重复审批打断，运行过程看得见，失败有原因、能够继续。<br>
> **核心做法**：修正 TUI 呈现，补齐失败诊断与有限重试，引入可撤销的工作区授权、SearchAPI 和根目录配置。<br>
> **边界**：沿用 Agent 持有生命周期，不引入 OS 沙箱，保留现有时间、并发和权限硬边界。<br>
> **风险 / 未验证**：历史停止原因只能部分还原，真实模型、Windows 终端体验与页面效果仍需实际验收。<br>
> **当前 / 请审阅**：实现与本地门禁已完成，真实终端、真实服务及主观效果的验收边界见 [Report](report.md)。

建档日期：2026-09-07。调查基线：`main @ cd3ac87`。开发者于 2026-09-08 确认 Spec，并明确要求按流程实现；真实外部服务调用与 Git 动作仍需单独授权。

## 问题

当前 Agent 已能执行 Coding 任务，但一次实际使用暴露出呈现、授权和失败恢复之间的断点。开发者看到的是反复批准、命令占住底部、工具没有动静，以及任务无解释地停止，难以判断应该等待、修正还是继续。

本次调查确认的事实与证据边界如下：

| 问题 | 当前事实与原因 |
| --- | --- |
| 调用次数限制 | Feature 008 和当前代码已移除单 Run 的 12 次、根与成员共享的 60 次模型调用截止。本次保持该结果，不重复建设；30 分钟共享任务时限仍存在 |
| 命令结果持续占据底部 | 流式运行期间执行 `/context`，结果追加在当前 Turn 之后，后续进展继续更新前面的 Turn，因而命令结果长期留在下方；空闲执行 `/mode` 时编辑框本身能够正常清空 |
| 工具过程缺失 | 参数生成阶段缺少可呈现事件；即使完整 ToolCall 已收到，TUI 也可能直到执行开始才创建工具卡片 |
| 错误难以发现 | 失败工具完成后同样被折叠，默认只显示 failed；模型流异常的安全分类没有完整传到 Session 与 TUI |
| 提交草稿消失 | `prompt` 返回 busy 等拒绝时，已清空的输入没有恢复为草稿；内容仍可能从输入历史找回，不能称为永久丢失 |
| 实际 Session 多次停止 | 所调查的 8 个 Run 中有 6 次 failed、1 次 aborted、1 次 completed。一次失败前输出用量为 15,999，接近 16,000 上限，但历史未保存结束原因；其余失败和中止同样缺少足够元数据，不能断定为限流、网络故障或用户取消 |
| 重复人工批准 | 同一 Session 有 11 次人工允许，集中在命令、编辑与写文件；运行模式为 agent，逐动作审批和缺少可复用授权共同造成中断 |
| 页面交付缺少实际验证 | 星球单页的 JavaScript 语法检查通过，但浏览器中 canvas 尺寸与球体容器不匹配，390px 视口出现横向溢出、导航超出视口；语法与标签数量检查未覆盖这些问题 |

上述 TUI 与模型错误传播问题已通过本地确定性场景复现，页面布局缺陷已在浏览器核对。历史 Session 的未知原因不能通过新代码补写成已知事实；页面的审美是否达标仍由开发者判断。

## 用户流程

1. 作为开发者，我希望在 Anthias 根目录配置一次模型和搜索服务，以便从不同项目启动时不再反复配置环境变量。
2. 作为开发者，我希望明确允许当前工作区的日常修改与任务命令，并选择记住授权，以便后续同类工作持续推进。
3. 作为开发者，我希望随时查看授权范围、来源并撤销，以便不必在方便使用和失去控制之间二选一。
4. 作为开发者，我希望执行命令后能立即看到结果，后续进展继续自然向下显示，以便命令结果不会长期占住输入附近的位置。
5. 作为开发者，我希望看到工具从准备参数、等待批准到执行完成的过程，以便知道 Agent 正在做什么。
6. 作为开发者，我希望失败、中止、等待重试有明确原因和下一步，以便不会把未知停止误认为任务完成。
7. 作为开发者，我希望恢复任务时保留已完成成果，以便不因重试或继续而重复执行副作用。
8. 作为开发者，我希望 Agent 能搜索网页并引用结果，以便 Coding 决策可以采用当前公开资料。
9. 作为开发者，我希望界面生成任务经过实际运行与布局检查，以便最终结果与交付声明一致。

正常流程为：加载 Anthias 本地配置 → 核对任务工作区及有效授权 → 接受输入并持续呈现进展 → 在授权内执行或明确说明阻塞原因 → 对可恢复的临时请求失败有限重试 → 验证产物并报告完成范围。失败后继续会开始新的 Run，并采用已持久化事实与当前有效授权。

## 已确认决定

| 方面 | 本次方向 |
| --- | --- |
| 次数限制 | 不因累计模型调用次数结束仍在推进的任务；沿用 Feature 008 已实现结果 |
| 配置 | Anthias 根目录使用被忽略的 `.env`，仓库提供 `.env-example`；不从任务项目自动读取模型密钥或权限配置 |
| 搜索 | 首个内建网页搜索使用 SearchAPI 的 Google 搜索接口，不建立多供应商体系 |
| 授权 | 保留 agent、plan、auto_allow；在明确用户授权基础上增加可记住、可查看、可撤销的工作区授权 |
| 审批顺序 | auto_allow 下，硬禁止与当前限制优先；已明确授权的动作由确定性规则放行，不能明确归入授权的动作再走 AutoAllow 审核，证据不足才交给用户 |
| 沙箱 | 本 Feature 不引入 OS 沙箱；工作区与 Git worktree 不构成 Shell 进程隔离 |
| TUI | 严格检查输入、命令、工具、审批、停止和恢复的真实交互；Agent 持有执行状态，TUI 负责呈现与输入 |
| 交付质量 | 用实际运行和与任务有关的验证支撑完成结论；页面任务纳入桌面与窄屏检查，不建设专用验证平台 |

以下行为合同已随 Spec 确认，实施与验收以此为准。

## 行为与失败

### 1. 启动与本地配置

- Anthias 根目录指程序自身的项目或安装根目录，与 `--workspace` 和启动目录无关。从其他目录启动或恢复 Session，仍读取同一份根 `.env`，不得加载任务项目中的同名文件。
- 根目录没有 `.env` 时生成不含凭据的本地配置文件，已有 `.env` 不覆盖。仓库提供可直接复制的 `.env-example`，包含现有模型变量、可选上下文与输出配置、`SEARCHAPI_API_KEY` 和 `ANTHIAS_PERMISSION_MODE` 的说明，模式默认填 agent，并说明如何改为 auto_allow。模型仍使用通用 OpenAI-compatible 配置，示例不产生模型专用分支。
- `.env` 与真实凭据不提交；模板只有变量名、占位符和非敏感默认值。首次仍需开发者填写自己的 Key，后续启动自动采用，不把“生成配置”描述成自动取得凭据。
- 同名变量以进程环境覆盖 `.env`，显式空值也不回退读取文件中的密钥。权限模式优先级为显式 `--mode` → 进程环境 → 根 `.env` → agent；非法模式不能静默回退到更宽松模式。
- 默认模式通过本地配置记住。运行中 `/mode` 继续只改变当前 Agent，受现有 busy 约束，不静默改写 `.env`。模式选择本身不授予任何工作区权限，恢复历史也不恢复旧授权。
- 配置缺失、格式错误或不可读时显示变量名或文件位置，不输出值。无法创建 `.env` 时明确告知；若现有环境已足够，仍可启动。缺少模型必需配置应在进入交互前失败；缺少搜索配置只影响搜索能力。
- 配置解析和 Provider 创建继续属于 Agent 的生产启动边界；TUI 不读取模型密钥、不构造 Provider。密钥不进入模型上下文、Session、Tool 结果或诊断报告。

### 2. 可复用的工作区授权

工作区授权是用户通过明确交互授予的一段权限范围，不是把项目文件判为可信，也不是一次批准自动变成永久允许。TUI 提供独立的查看、授予与撤销入口，展示规范化后的工作区路径、允许的动作类别、有效范围和是否记住。

- 授权面向当前任务工作区。日常范围包括该工作区内的普通文件创建与编辑，以及完成任务所需的本地构建、测试、检查和开发命令。读取继续采用现有规则。它不自动包含无关外部路径写入、破坏性清理、Git 提交或远端发布等超出该范围的动作。
- 用户可以仅授权本次会话，或明确选择记住。记住后在同一规范化工作区重新启动可复用，不因父目录、同名目录、相邻项目或历史 Session 自动扩展。授权失败或保存失败必须显示实际结果，不能提示已记住。
- 持久授权由 Agent 管理的本地记录保存，与模型可维护的记忆、项目规则和会话回放分开。用户交互是新增或扩大该授权的唯一入口；AGENTS.md、搜索结果、MCP 内容、模型消息和其他 Agent 消息均不能自行授予权限。
- agent 模式保留逐动作审批行为，plan 保持只读；仅 auto_allow 消费可复用授权。已有单次批准仍仅允许对应动作，不推导为同类动作授权。
- auto_allow 每次准备执行时，先应用硬禁止和当前用户限制，再核对实际路径、动作与有效授权。文件动作按最终规范路径匹配；命令只对授权面板列明并获准的命令入口、参数范围和工作目录做确定性匹配，组合命令需逐段符合。无法解析、间接拼装或不在该范围的命令转 AutoAllow 审核，不能仅凭 cwd 或“看起来像测试”放行。命中授权就执行并标明来源，审核仍无法确认授权时才请求用户；同一有效授权内不能仅因“之前审过”而转回人工批准。
- 自动放行不是对任意 Shell 文本的可靠静态证明。授权本地命令意味着允许执行任务需要的本地程序及项目代码；界面在授予时说明它们以当前系统用户身份运行，可能访问工作区之外。能识别的越界动作仍按权限处理，不宣称 cwd、字符串检查或 worktree 可以约束所有运行时副作用。
- 成员从根任务继承的权限不得大于根用户授权。授权面板单独选择是否包含成员 worktree：仅本次会话授权只覆盖当前任务创建并登记的成员 worktree；选择记住并包含成员时，覆盖今后从同一根工作区发起任务所创建并登记的成员 worktree。界面在授予前显示这个跨任务范围，未选择时不继承，其他工作树不自动继承。成员请求继续显示来源、工作区和动作。
- 撤销入口在运行期间可用，立即使尚未开始的相关动作及成员授权失效，并作为当前限制参与后续判定；撤销前的用户记录或自动审核结论不能重新恢复该范围，恢复需要撤销后的新显式用户授权。已开始的动作支持现有停止流程，不承诺回滚或撤销已经产生的副作用。撤销会使相关待批准请求失效，过期按钮不能再次放行动作。持久撤销保存失败时，当前 Agent 树先失效，明确提示“本次已撤销，跨启动撤销未保存”，不得宣称旧记录已删除。
- 新的用户拒绝或缩小范围优先于旧允许。恢复 Session、切换项目或成员继续任务时重新核对当前权限；历史批准只作为历史展示。准备完成后的执行前复核、批准与执行开始事实的持久化顺序继续保留。

授权来源使用简短标签显示，如“工作区授权”“本次批准”“自动审核”；详情可查看范围与原因，不把每个自动允许都渲染成需关闭的弹窗。没有 OS 隔离时，本地授权记录也不提供抵抗当前系统用户任意程序篡改的保证。

### 3. TUI 输入、命令和阅读位置

- 普通命令的结果进入发生位置对应的对话时间顺序，显示命令名与结果摘要；后续 Agent 进展必须出现在其后。命令输出不得成为长期固定在当前 Turn 下方或输入区上方的额外区块。
- 长结果采用有界摘要和可展开详情，不无界挤占主视图。用户能关闭详情、返回输入；短结果无需额外确认。主动打开的阅读详情与等待批准保持可访问，不因背景事件被任意抢走焦点。
- 输入仅在已接受后视为提交成功。Agent 拒绝 busy、参数错误或状态不允许时显示原因并保留可编辑草稿；异步拒绝到达时若用户已输入新内容，不覆盖新草稿，并保留恢复上一份输入的入口。输入历史不是唯一恢复方式。
- 不在本 Feature 增加隐式排队。运行中不支持的新 prompt 或命令明确说明限制；支持的只读命令、停止和授权撤销继续可用，不因正在生成文本而整块锁住输入。
- 检查多行和长中文输入、粘贴、历史导航、命令错误、窄终端、窗口缩放、应用内滚动及滚动跟随。用户上翻阅读时不强拉到底部，回到底部后可继续跟随；已执行命令不得残留为可再次误提交的编辑内容。
- 焦点切换、关闭详情、停止 Run 和退出程序各有清晰反馈；沿用现有按键语义，不让一次按键同时触发关闭面板与业务中止。退出后恢复终端状态并关闭由本次运行持有的资源。

### 4. 工具与操作过程可见

- 同一个 ToolCall 按稳定身份展示参数生成、等待批准、执行中以及完成状态。模型开始形成工具请求时即显示工具名与阶段；路径或目标尚不完整时显示“参数生成中”，不能伪造目标或提前执行。
- 完整 ToolCall 已产生但尚未开始执行时仍必须可见。事件通过 AgentEvent 到达 TUI，TUI 不从文本猜测动作状态；不完整参数不构成可执行请求，也不将未验证片段直接输出为详细参数。
- 执行开始、完成、失败、中止、拒绝和结果未知具有可区分的表现。快速工具也留下摘要；并发或成员工具不串行错配、重复建卡或覆盖彼此状态。
- 成功结果默认显示有界摘要，必要时打开详情或已有 Artifact。失败默认露出安全的具体原因与可采取的动作，不能只有 failed 标签；Run 结束后仍保留错误摘要与展开入口。
- 审批等待显示动作、来源和授权范围；批准、拒绝、撤销或 Run 结束后及时解除等待状态。长时间执行显示当前阶段和可用的停止方式，不伪造进度百分比。
- Skill、MCP、协作、Git 等已有命令或语义操作同样展示开始、结果和失败；用户命令不伪装成模型 ToolCall。MCP 能力调用和成员动作沿用真实身份与事件来源。
- 对实际使用中出现的 Tool 输入错误，核对模型可见的 Schema、说明与运行时校验是否一致。路径、搜索基准和替换参数错误需指出期望形态，允许模型在原任务内修正；不以放宽越界或无效参数校验换取成功率。

### 5. 停止原因与有限恢复

Agent 必须区分完成、失败、主动中止和资源截止，并向 TUI 与 Session 传递同一份安全原因。用户看到的是“发生什么、是否会重试、现在能做什么”，而非无说明地结束流。

- 新产生的记录保存可确认的结束类别、Provider finish reason、可用的 usage，以及重试次数和中止来源。安全错误包括上下文不足、输出达到上限、认证或配置错误、限流、暂时网络或服务错误、无有效内容的异常结束和未知错误；只保存实际可获得的事实。
- 中止来源至少区分用户停止、任务时限、程序关闭、父任务取消和可识别的内部中止。旧记录或无法确认的原因显示“未知”；缺失 usage 保持未知，不补成零，也不根据 token 接近上限倒推出确定原因。
- 原始请求、响应体、密钥、带凭据 URL 和任意异常堆栈不直接进入界面或持久诊断。错误分类、HTTP 状态等元数据只保留安全字段；开发者可查看有界诊断摘要，不要求翻阅原始 JSONL 才知道为何停止。
- 普通模型生成遇到可识别的暂时网络错误、限流或可重试服务错误，且尚未向用户显示正文、Reasoning 或工具参数片段，尚未接收完整 ToolCall 时，自动重试最多额外 2 次。仅显示请求或工具准备阶段不算已交付这些内容。采用有上限的退避，尊重可用的服务端等待信息及剩余任务时限；等待过长或时间不足时明确结束并说明原因。
- 重试等待与次数显示在 TUI，用户可以停止；取消后不再发出下一次请求。重试和等待均计入现有共享任务时限，不因重试重置 30 分钟计时。
- 认证、配置、无效请求、未知错误、输出截止，以及已经显示正文、Reasoning、工具参数片段或接收完整 ToolCall 后的失败，不进行上述自动重试。上下文溢出继续走现有有界压缩恢复，不叠加一套无限恢复循环；不完整 ToolCall 不执行。
- 本次普通生成重试不扩展到压缩请求、AutoAllow 审核或 Tool 执行。保留同一上下文最多一次强制压缩、同一动作既有审核次数，以及 MCP 或命令结果未知时不自动重放的约束。已开始但结果不明的副作用不能改称未执行。
- 自动恢复耗尽或不适用时，保留已完成消息、Tool 结果和产物，给出简短原因与继续入口。用户确认继续或输入后续要求才开始新的 Run；继续采用已持久化事实，重新判断剩余工作，不重放成功工具、审批或 Git 操作。
- 有失败、截断或尚待处理的工具请求时，不得仅因出现结束事件就显示“任务完成”。单个工具的可修正输入错误可以回到 Agent Loop 处理；不能把每次工具失败直接升级为整个任务停止。

本 Feature 不承诺还原历史 Provider 的原始错误，也不保证重试能解决此次历史会话的全部停止问题。

### 6. SearchAPI 网页搜索

- Agent 新增内建 `web_search`，接收非空 query 和可选正整数 page，默认第一页。使用 SearchAPI Google 搜索，返回标题、URL、摘要、来源及当前页信息；无结果也是正常结果。
- 请求使用固定服务端点与 Header 携带凭据，模型不能指定任意目标域名或取得 Key。返回内容与现有 Tool 预览一样有界；不自动抓取全部页面，也不把结果页数当作需要取消的模型调用次数限制。
- 未配置 `SEARCHAPI_API_KEY` 时 Agent 可以启动，并明确说明搜索不可用及需要的变量名，不能假称已联网。无效凭据、配额或限流、超时、网络错误、服务异常与用户取消分别返回可理解结果，不泄露原始响应中的敏感内容。
- 搜索作为只读网络能力，在已配置该服务且当前任务需要搜索时使用，沿用只读工具并发、取消与权限规则；plan 可以搜索。工作区授权不自动变成任意网络外发授权，不主动附带项目文件、密钥或完整会话作为 query。
- 搜索开始与结束在 TUI 可见。结果作为带来源的不可信外部事实进入上下文，不提升权限、不作为系统指令；只有摘要时不得声称已经阅读全文。最终使用结果支撑主张时给出相应来源链接。
- 实现按 [SearchAPI Google 官方文档](https://www.searchapi.io/docs/google) 核对请求与响应合同；不依赖任意每页结果数承诺。本 Feature 不建设浏览器自动化平台、网页抓取管线或搜索供应商 Registry。

### 7. 任务交付与实际效果

- Coding 任务根据用户要求选择最小有效验证；先明确成功表现，再生成或修改。完成时说明做了什么、运行了什么验证、哪些结果仍需人工确认，不把“写出文件”直接等同于“达到效果”。
- 页面任务在具备浏览器能力时检查实际渲染、控制台、主要交互、桌面与窄屏布局。可使用已有 MCP 或经授权的命令能力；不要求 Agent 核心新增专用页面框架或内置截图协议。
- 本次以星球单页问题作为回归场景：检查绘制内容与球体容器尺寸、横向溢出、窄屏导航和主要切换交互，并保留对应版本与视口的证据。原始外部文件作为调查材料，验证使用获准的测试工作区或副本，不把重写该项目直接并入产品源码。
- 缺少浏览器或执行权限时明确报告“页面效果未验证”，不能用语法检查冒充视觉验收。自动检查不能证明审美达标，未来简约风等主观要求仍需开发者实际查看。
- 验证发现缺陷应在当前授权与任务时间内修正后复查；不能完成时交代剩余问题。不得通过隐藏失败、虚构截图或将未验证项目标为通过来达成交付。

## 职责、持久化与既有合同

Agent 继续持有模型请求、重试、授权与撤销、Tool 副作用和 Session 事实；TUI 只持有草稿、焦点、展开状态和阅读位置。新增能力使用现有 Agent Interface 的语义行为与有序 AgentEvent，不向 TUI 暴露 Provider 类型、模型内部步骤或权限规则实现。

新增授权记录独立于 Session；会话中的授权来源只是当时事实，恢复时不能代替当前权限。新增失败与尝试元数据需兼容现有 Session：旧数据仍能查看和继续，未记录字段标为未知；回放不触发模型、工具、审批或外部请求。若持久化失败，继续遵守现有先记录后执行和明确失败规则，不能为了少弹窗而绕过。

本 Spec 确认后，下列新合同替代对应旧约束；旧 Report 的已验证事实与原 Feature 状态不被改写。跨 Feature 文档在相应流程阶段同步，未完成的能力不宣称已经实现。

| 既有合同 | 本次变化与保留项 |
| --- | --- |
| [Feature 003](../feature003-tool-execution-safety/spec.md)、[Feature 005](../feature005-context-engineering/spec.md) 的逐动作审批与单次允许 | auto_allow 新增显式工作区授权；agent、plan、硬禁止、执行前复核与单次批准不扩权仍保留 |
| [技术基线](../../docs/technical-baseline.md) 中暂缓的可复用授权与通用网络重试 | 本次仅纳入上述工作区授权及普通生成的有限暂时失败重试，不扩展为通用重试或权限框架 |
| [Feature 006](../feature006-command-skill-mcp-tui/spec.md) 的 TUI 与 MCP 合同 | 修正命令顺序、草稿和完整过程展示；不改变 TUI 与 Agent 职责，也不重试执行结果未知的 MCP 调用 |
| [Feature 007](../feature007-multi-agent/spec.md) 的成员权限与恢复 | 工作区授权只有显式包含登记的成员 worktree 才继承；成员不能扩大权限，恢复不重放副作用 |
| [Feature 008](../feature008-memory-and-prompt-orchestration/spec.md) 的调用与来源边界 | 12 / 60 次截止继续移除；记忆与来源不能授予权限，30 分钟共享时限及既有上下文压缩继续保留 |

不移除单批 32 个 ToolCall、4 个纯只读并发、最多 3 个成员、模型上下文与输出容量、Tool 输出预览和网络超时等不同性质的边界。实际触发时应说明触发的是哪一项，不能笼统称为“次数用完”。

## 不在范围内

- OS 沙箱、系统级进程隔离、全自动无人值守安全保证，或取消所有权限与资源边界。
- Desktop、独立 Host、新协议层、通用权限平台、多搜索供应商体系和专用工程验证平台。
- 无限模型重试、自动重放未知副作用、保证恰好执行一次，或根据不完整历史猜测停止原因。
- 重新设计整个 TUI 命令体系、改变已有 Agent 业务归属，或将星球页面模板写入 Agent 核心。
- 自动取得真实密钥、未经单独授权调用真实模型或付费服务、改写外部 HTML、提交或推送。

## 2026-09-08 后续修复合同

开发者已根据实际 Session 诊断授权直接修复，沿用本 Feature，不新建 Feature 或 Stage。

- 自动审核保留真实用户任务及全部后续限制；历史单次批准保留审计，不携带文件正文参与新动作授权。完整用户来源与动作不能纳入预算时明确降级，不静默裁掉限制。
- 工作区命令可由用户登记精确命令，或显式允许其字面参数前缀及后续参数，并指定确切的工作区内 cwd。先展示再确认，默认继承当前记住/成员选项，旧记录不扩大。组合命令逐段匹配，动态展开与重定向仍转审核；明确可识别的清理、Git 写入或发布不因此放行。允许解释器前缀意味着可以运行其任意字面脚本参数，不提供 OS 隔离。
- 普通输出默认预算为 64,000；上下文窗口不超过 84,000 时沿用 16,000，再按模型能力收窄并尊重显式配置；摘要与审核不跟随扩大。增加普通生成和审核独立的可选思考强度配置，未配置不发送可选参数，大文件按合理片段生成。
- 安全诊断增加可选思考 token、受控错误代码/字段和无正文的请求结构计数，旧记录仍可读取且缺失保持未知；新增诊断不视为已还原历史 HTTP400。

| A11 | 本地构造输出截止、上下文不足、认证失败、暂时网络错误、无有效内容及未知异常，TUI 与恢复后的 Session 显示一致的安全分类；缺失字段保持未知 |
