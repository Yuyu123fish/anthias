### 实际修复

**审核来源。** 新审核只把真实用户消息原文作为授权来源，按原顺序保留；历史单次批准继续保存在 Session 中供审计，不再携带大段文件内容参加下一动作的授权判断。完整用户来源或动作超预算时明确说明，不静默舍弃原始任务或后续限制。审核预算仍为 8,000 输入 / 2,000 输出，并区分预算不足、输出截止、JSON 解析失败和模型调用失败。

**工作区与命令授权。** TUI 在 AutoAllow 没有有效工作区授权时提示入口。新增 `/permissions command [--remember] [--members] [--prefix] [--cwd <相对目录>] -- <命令>`，合并当前命令并继承当前记住/成员选项；先展示完整范围，再输入 `grant` 确认。普通工作区文件使用既有显式授权，其他命令可精确登记，或通过 `--prefix` 允许后续字面参数。用法见 [Quick Start](../../quick-start.md#工作区授权)。

命令匹配按参数边界与确切 cwd 检查，每段组合命令分别匹配；真实路径在执行前重新核对，外部 junction 不生效。动态展开、重定向、不确定语法以及可直接识别的 Git、清理、发布入口继续审核。独立审查发现单独 CR 被当成参数空白的问题，现已与 LF、CRLF 一样作为命令边界，并加入回归。解释器前缀仍允许字面脚本的系统用户能力，不构成 OS 隔离。

授权预览与工具待批准互斥，范围改变或撤销会使旧预览失效；登记范围不等于批准当前待执行动作。最多 49 项、完整记录 192,000 字节，非法或过大输入保留原授权，不先写入无法重读的记录。本次未代用户创建实际工作区授权。

**长生成。** 普通输出默认由 16,000 提高到 64,000；上下文窗口不超过 84,000 时沿用 16,000，再按模型输出能力收窄。显式配置仍优先且超限拒绝，摘要 8,000、审核 2,000 不变。Coding 规则要求大文件合理分段，截断后核对已执行工具和剩余工作，不把未完成 JSON 当成已写入文件。

新增 `ANTHIAS_RESPONSE_REASONING_EFFORT` 与 `ANTHIAS_APPROVAL_REASONING_EFFORT`，分别用于普通生成和审核，支持 `low` / `medium` / `high`；未配置不传。两份配置模板已同步；本机被忽略的 `.env` 仅补入这两个非敏感选项为 `low`，没有输出或改写已有凭据。重新启动后加载，进程环境仍优先。预算与思考强度调整可以减少已知截断风险，不保证所有长任务不再停止。

**后续诊断。** Model Adapter、Session 和 TUI 保留可选 `reasoningTokens`、白名单 Provider 错误码、标准参数路径，以及请求用途、预算、消息和 Tool 配对等有界计数。思考用量属于输出分项，不重复汇总；不保存请求正文、任意错误字符串或异常堆栈。后续 HTTP 400 可以带上实际可获得的信息，历史缺失字段仍为未知。

### 接口与兼容性

- `permissions.grant` 增加可选 `commands`，`WorkspaceCommand` 增加可选 `allowArguments`。省略时仍使用原默认列表；TUI 负责合并预览，Agent 校验并持有最终范围。
- 工作区授权磁盘版本仍为 1。旧记录按原精确范围读取，不自动扩大；支持当前命令集合的快照、重新打开与撤销。
- Session Schema 仍为 3，新诊断字段和请求思考用量均可选。旧记录可以恢复，缺失不补零；不持久化完整 Reasoning 正文。
- 本地实际 HTTP 请求验证了同一 Run 的 Reasoning 续传及 Tool 配对，也验证了下一 Run 清除瞬态 Reasoning；没有发现足以确认历史 400 根因的协议缺陷。
- 没有新增依赖、package 或公开生命周期；30 分钟任务截止、并发、取消、有限重试与现有权限硬限制保留。
