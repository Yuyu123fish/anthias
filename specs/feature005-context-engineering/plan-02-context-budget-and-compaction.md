## 2. 配置与内部合同

模型能力与应用策略分开。原有三个模型配置变量继续有效，新增以下可选入口：

| 环境变量 | 含义 | 默认 |
| --- | --- | --- |
| `ANTHIAS_MODEL_CONTEXT_WINDOW` | 覆盖模型窗口容量；未知模型必须提供 | 已知模型能力数据 |
| `ANTHIAS_MODEL_MAX_OUTPUT_TOKENS` | 声明模型可用输出能力 | 已知模型能力；自定义模型可补充 |
| `ANTHIAS_RESPONSE_MAX_TOKENS` | 普通请求输出策略 | 16,000 |
| `ANTHIAS_COMPACTION_MAX_TOKENS` | 摘要请求输出策略 | 8,000 |
| `ANTHIAS_CONTEXT_KEEP_TOKENS` | 保留原文目标 | 32,000 |

安全余量固定为 20,000，不要求用户逐模型配置。默认输出策略受已知模型输出能力约束；显式无效数值、超过已声明能力或无法留下请求空间时在启动前拒绝。未知模型不能使用任意窗口回退；仅声明窗口而未声明输出能力时，应用输出策略不被冒充为 Provider 能力。

首期内置 `deepseek-v4-flash` 的已核验能力数据：上下文 1,048,576，模型版本 DeepSeek-V4-Flash-0731；官方输出标为 384K，应用保守使用 384,000 的可用上限。来源为 [官方集成配置](https://api-docs.deepseek.com/quick_start/agent_integrations/codex/) 和 [模型说明](https://api-docs.deepseek.com/quick_start/pricing/)，核验日期 2026-09-05。生产 Adapter 不按此模型建立条件分支。

内部 ModelRequest 增加调用用途与显式输出额度，finish 携带归一化 usage。SDK 将缺失字段补为零时，必须结合原始标准 usage 字段是否存在来保留未知；缓存不从上下文占用中扣除，也不重复计入总输入。Provider 原始错误只转换为安全失败分类，其中上下文超限可由 Context 识别。

生产装配必须传入已解析能力。内部确定性 ModelStream 工厂可以使用明确的测试窗口默认值；这个默认值不用于未知生产模型。

## 3. 请求、选择与压缩

Context 在现有 ModelStream 调用边界包装每次普通请求，包括 Tool 后续调用。完整 Session 历史仍归原持有者；发送投影由最新有效压缩、稀疏用户引用、完整尾部和新增消息构造。当前 Run 的临时 Reasoning 仅在实际重发时计入输入。

用量锚点仅在模型、固定前缀、工具定义与压缩投影一致，且原请求消息仍是当前请求的精确前缀时复用；只估算新增内容。恢复后不能证明锚点有效时重新估算。统计分别归属 response / compaction / approval，缺失用量与已知总量分别表达。

触发线与发送条件严格使用 Spec 公式：`I >= C - 20,000 - max(O,Q)`；普通请求与摘要分别检查输入加对应输出额度。静态前缀、最新完整 User 与必要输出空间不能共存时直接说明容量不足。

选择按完整消息与 Assistant ToolCall/全部结果组进行；最新 User 必保留，较新真实用户输入优先，尾部以完整组保留。保留目标同时受实际窗口限制。摘要输入只含上一份摘要及本次退出原文区的内容；来源 Entry ID 保留用于说明事实，摘要不能创造授权。

摘要禁用工具，使用当前模型，按固定栏目保留目标、约束与偏好、决定、完成及验证边界、当前进度、文件/错误/产物。最多八个中间摘要阶段，每阶段必须推进完整交互组；单条旧消息无法放入、空输出、栏目缺失、截断、工具调用或无覆盖进展时失败。中间结果不提交检查点。

顺序为：生成并校验摘要 → 检查最终请求仍有余量 → fsync CompactionEntry → 更新索引 → 切换内存投影 → 自动继续。取消不会继续原任务，索引失败不撤销已落盘事实。对 Provider 上下文超限最多强制恢复一次，且必须存在自上次压缩后新增的可压缩进展。

活动 Run 通过 lease 写入 usage/compaction 并带 `runId`；兼容 Plan 01 尚未携带该字段的合法记录。新引用仍在写前校验，非法旧压缩只影响检查点选择，不破坏原始历史。

## 4. 协作与验证

先固定模型事件、预算与选择接口，再并行完成模型适配、纯选择和摘要三个边界；主 Agent 持有 Context 装配、Agent/TUI 集成及最终门禁。交接只报告合同、修改范围、测试结果和剩余阻塞，避免逐轮扩展检查范围。

定向验证集中覆盖：用量缺失/缓存、中文与英文估算、阈值相等、Tool 后再次预检、用户原文优先及 Tool 组完整、增量摘要、恢复去重、取消/失败不提交、超限只恢复一次。只为这些行为增加测试，不为目录迁移单独堆叠测试。

阶段末执行 `pnpm verify`。一次有界 Standards/Spec 审阅只处理影响本阶段验收的具体问题，修复后补受影响验证，不开启新研究。真实模型优先用两个请求覆盖摘要与继续，使用临时数据根和较小的明确配置窗口；全 Feature 实际请求合计不超过六次，失败计数。凭据只从已授权的环境变量进入进程，不入仓库、日志或原始请求快照。
