## 2. 独立审核合同

auto_allow 使用同一当前模型的一次独立请求，purpose=approval、tools=[]，输入最多 8,000 token、输出最多 2,000 token，同时满足模型窗口减去 20,000 安全余量。审核不经过普通回复的压缩控制器，不修改主对话历史，但使用同一 Run 的取消信号和持久用量账本。

输入包含已准备动作的名称、目标、完整预览、风险与执行边界、不可变动作指纹；授权来源只选真实 User Entry 和已有人工批准事实。系统提示、摘要、Assistant 自述、Tool 结果和外部文件均不能成为授权。优先选近期完整来源；具体动作本身或必要来源无法装入预算时直接转人工，不能截断后自动放行。

返回严格 JSON：decision 为 allow / needs_user / deny，reason 为简短解释，authorizationEntryIds 只能引用实际提供的可信来源。allow 必须引用至少一个真实授权来源；非 stop、格式无效、字段异常、引用无效、拒绝、调用失败或授权不足均转人工。取消直接停止，不再人工等待。审核最多对本次待执行动作调用一次；同一 Run 按动作指纹去重，换 ToolCall ID 不产生新授权，用户已拒绝的相同动作不能自动重审。

模型只决定准备动作是否已有充分授权；高风险且已明确授权的动作可以批准。固定 hard deny 在审核之前生效，任何模式均不可覆盖。审核内部 Reasoning 不进入主对话、事件或审批记录。

## 3. 动作绑定与事实顺序

Tool 准备阶段生成动作指纹，绑定命令与 cwd/Shell，或文件真实路径、预期身份/内容与待写内容。现有命令 cwd 与文件指纹重验继续在执行前生效，变化时形成明确失败，必须通过新的 ToolCall 重新准备，旧批准不可复用。

ApprovalDecisionEntry 兼容旧格式，新增可选动作指纹及具体批准标识；真实运行新记录包含这些字段，自动、人工、确定性策略来源分开。授权引用仅允许较早真实用户输入或较早人工允许事实，禁止引用摘要/工具/自动批准自我扩权。

任何副作用执行都通过同一持久入口：先保存对应允许决定，再保存 ToolExecutionStartedEntry，成功后才发起实际写入或命令。不能依赖有无人工 approval ID 判断是否记录。读工具仍维持现有并发，不为纯读取增加副作用开始记录。

取消优先于迟到批准；审批或开始事实写入失败时停止当前 Run，不执行动作。已有人工确认事件和公开响应方式保持兼容，新增 reviewing_tool 阶段与自动审核来源/降级说明；模式只能空闲切换。
