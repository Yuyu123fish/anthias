## 1. 问题与目标

当前 Agent 在每轮模型调用中使用累积的消息历史，没有上下文容量判断、状态压缩或压缩后的恢复路径。Model Adapter 只保留完成原因，未向 Agent 传递 usage，普通请求也未显式约束回答输出预算。长任务只能不断增加输入，直到触及 Provider 限制。

Session 当前使用 Schema 1 的平铺线性 JSONL。历史加载与模型输入没有分开，格式尚不能记录压缩覆盖范围、保留用户消息或独立恢复位置。工具输出超过现有字节、行数限制后会被截断，原文无法再次访问；多个工具的输出合计也缺少上下文预算。

Agent / Plan 模式已经提供确定性的 Tool Policy，但执行命令等操作会逐次要求人工确认。随着任务变长，反复确认和不断增长的上下文共同打断执行。工具原文落盘后，还需要明确它与 Session 的共同生命周期，避免数据长期堆积。

本 Feature 完成以下用户结果：

- 长任务在模型调用前主动检查容量，必要时压缩，成功后自动继续原任务。
- 用户仍能读取保留期内的对话历史；模型只接收当前需要的上下文。
- 用户要求、纠正、偏好和表达方式在压缩时优先保留原文。
- 大工具输出有受限、可再次读取的原文位置，同时保持模型输入和内存有界。
- AutoAllow 自动处理有充分授权的操作，把授权不足或无法判断的情况交回用户。
- Session 按创建时间分层归档，超过两周未使用的会话及其产物在启动时后台清理。

## 2. 用户故事与流程

1. 作为持续完成编码任务的用户，我希望上下文接近容量时自动整理并继续，以免重新说明任务。
2. 作为提出过要求和纠正的用户，我希望这些原话优先保留，以便 Agent 延续我的意图和表达习惯。
3. 作为重新打开对话的用户，我希望既能查看已有历史，又能从最近一次有效摘要继续，以免整段历史再次挤满模型窗口。
4. 作为检查命令或搜索结果的用户，我希望过长输出可以按需取回，以便核实预览之外的信息。
5. 作为开启 AutoAllow 的用户，我希望任务范围内的操作顺畅执行，遇到需要我作新决定的情况才停下来确认。
6. 作为需要中止任务的用户，我希望压缩、审核和工具执行都能停止，以免出现取消后仍继续执行的操作。
7. 作为使用自定义模型的用户，我希望应用自动管理压缩余量，只有无法识别容量时才补充模型能力配置。
8. 作为长期使用 Anthias 的用户，我希望会话按时间归档，过期会话和工具产物共同清理，以便控制本地数据积累。
9. 作为正在查看旧会话的用户，我希望它在空闲时也受到保护，以免后台清理删除当前打开的数据。
10. 作为遇到断电、索引损坏或迁移失败的用户，我希望已保存的对话仍能恢复，错误能够明确说明，以免无声丢失历史或重复执行工具。

正常长任务的主流程为：接受用户输入 → 构造待发送上下文 → 检查预算 → 必要时压缩并持久化 → 调用模型 → 执行已获许可的 Tool → 形成有界结果 → 再次检查预算并继续。压缩、审核均在同一 Agent 生命周期内完成，不产生新的用户任务。

## 3. 术语、数据权威与默认参数

### 3.1 数据权威

| 对象 | 含义与持有者 |
| --- | --- |
| 对话历史 | Session 已保存的用户、Assistant、Tool 消息及相关事实；压缩不会删除这些记录 |
| 模型上下文 | 当前一次请求实际使用的固定指令、摘要、保留原文和工具定义；由 Agent 内部的 Context Module 构造 |
| CompactionEntry | 一次成功压缩的摘要、覆盖范围、保留引用和用量信息；保存在 Session JSONL 中 |
| 工具产物 | 归属一个 Session 的工具原文文件；由 Session 管理，消息保存有界预览及引用 |
| 恢复索引 | 单个 Session 的可重建旁路缓存，用于快速定位压缩记录及保留原文 |
| Session 定位索引 | Session ID 到归档相对路径的可重建缓存，不承担历史或清理时间的事实权威 |
| 最近使用时间 | 从 Session 的真实使用记录推导的 `lastActivityAt`；与创建目录、文件修改时间分开 |

Session JSONL 是会话事实源。两个索引丢失均不得导致会话丢失；索引更新也不得被当作用户使用会话。正在流式生成的临时内容、模型私有配置和 TUI 渲染状态不成为另一份持久事实源。

### 3.2 首期默认值

下列 token 数量使用十进制；MiB 使用 1,048,576 字节。这些是首期策略默认值，不代表已经通过真实负载证明最优。

| 参数 | 默认值 | 合同 |
| --- | --- | --- |
| 安全余量 S | 20,000 token | 独立于摘要输出预算保留，不因普通请求或工具输出变大而自动取消 |
| 普通回答输出上限 O | 16,000 token | 每次请求显式设置，包含 Provider 计入输出的 Reasoning |
| 摘要输出上限 Q | 8,000 token | 摘要请求单独设置和检查 |
| 原文保留目标 R | 32,000 token | 包含优先保留的用户原文与近期完整交互；不是字符串截断线 |
| 单个 Tool 结果预算 | 4,000 token | 包含预览、状态与产物访问说明 |
| 同批 Tool 结果合计预算 | 8,000 token | 同一 Assistant 回复产生的整批 Tool 结果共享 |
| 单个产物磁盘上限 | 32 MiB | 超限后明确标记不完整 |
| 单个 Session 产物合计上限 | 256 MiB | 包括已写入和并发写入中的产物占用 |
| 自动审核输入预算 | 8,000 token | 精确待执行操作必须完整放入，授权依据不足则转人工 |
| 自动审核输出上限 | 2,000 token | 独立调用，不使用普通回答的输出额度 |
| 会话保留期 | 14 × 24 小时 | 按最近真实使用时间判断 |

模型能力、应用策略分别配置。已知模型从内置能力数据取得上下文窗口和输出上限，允许明确覆盖；不根据模型名字中的数字猜测容量。模型能力数据需要标明来源和版本，生产调用继续使用通用 OpenAI-compatible Adapter。

普通用户不需要逐模型填写安全余量或摘要预算。未知自定义模型无法可靠取得容量时，启动提示补充一次窗口容量，不能把 usage 或任意回退值当作已确认容量。有效输出上限不得超过已知的模型输出能力；应用参数由 Agent 统一解析和校验，TUI 不读取模型配置。配置入口的具体拼写在 Plan 中固定。

## 4. 上下文预算、压缩与请求编排

### 4.1 用量归一化与估算

- Model Adapter 向 Agent 返回可用的输入、输出及缓存用量，缺失值保持未知，不能伪装为零。
- 缓存读写 token 必须按 Provider 字段语义归一化；已包含在输入总量中的部分不得重复相加。缓存命中不能从上下文占用中扣除。
- 能使用有效 usage 时，以它校准对应请求，再估算之后新增且将被再次发送的消息、工具结果及结构开销。不能把上一请求的用量当成下一请求的完整输入。
- 不能直接把上一请求的全部输出 token 加回输入：未再次发送的 Reasoning 等内容不占下一次模型输入。
- 没有可用 usage 时，估算整个待发送请求。首期文本估算按中文约一字一 token、普通英文约三个字符一 token，并计入 JSON、工具定义、角色和消息封装开销；它是保守启发式，不宣称等于 tokenizer。
- 更换模型、修改固定前缀、压缩或改变历史投影后，旧 usage 锚点不能跨版本直接复用，必须重新估算并等待新的有效响应校准。
- 用量归属普通回答、摘要或审核调用，分别统计；窗口容量、当前输入占用和累计调用用量在语义上分开。

### 4.2 每次发送前检查

检查发生在每次普通模型调用之前，包括一个 Run 内 Tool → Model 的后续调用。检查对象必须包含最新用户输入、刚完成的工具结果、固定指令及工具定义。

设 C 为有效上下文窗口，I 为完整待发送输入的用量判断，O、Q 为已按模型能力约束的输出上限，S 为安全余量。满足以下条件时，必须先压缩：

`I >= C - S - max(O, Q)`

这同时保留至少“20k 安全余量＋摘要输出”所需空间，并在普通回答输出更大时提前处理。以 C = 128,000、默认 O 和 Q 为例，触发线为输入 92,000 token；该例仅说明计算方式，不指代某个具体模型。

发送前还必须分别保证：

- 普通请求：`普通请求输入 + O <= C - S`。
- 摘要请求：`摘要请求输入 + Q <= C - S`。
- 审核请求：`审核请求输入 + 审核输出上限 <= C - S`，且满足独立审核输入预算。

摘要和审核使用各自的输入构造，不递归进入普通对话的自动压缩流程。固定指令、完整最新用户请求与必要输出空间已经无法共存，或没有可压缩历史时，停止当前请求并说明容量不足；不截断最新用户请求，也不继续发送已知超限的请求。无效容量或预算组合在请求前报错。

### 4.3 原文选择与摘要内容

原文选择遵守以下顺序与约束：

1. 最新用户请求完整保留。历史中的真实用户输入优先于旧 Assistant 解释和重复工具输出，较新的要求与纠正优先。
2. 用户原文计入 R，不额外无上限叠加一份用户历史。最新请求本身超过 R 时允许超过保留目标，但仍须通过实际请求预算检查。
3. 近期交互以完整消息和工具调用组保留。Assistant 的 ToolCall 与全部对应终态结果成组处理，不形成孤立 ToolCall 或 Tool 结果。
4. 可压缩一个长 Run 内已经完成的较早交互组；正在生成的消息、未完成的工具调用不作为压缩切点。
5. 尾部之外保留的用户消息通过 Entry 引用记录，恢复后按原有先后顺序呈现并去重，不能作为新的用户请求再次执行。
6. 更早且确实放不下的用户原文进入摘要，保留有效要求、纠正和偏好及其来源。后续明确纠正覆盖旧要求，不把临时任务要求升级为永久偏好。

摘要增量输入为“上一份有效摘要＋本次将退出原文保留区的内容”，不在每次压缩时重新提交全部历史。摘要使用当前模型，禁用 Tool，并覆盖任务目标、用户约束与偏好、关键决定及理由、已完成工作与验证边界、当前进度与下一步、相关文件/错误/工具产物引用。

摘要必须区分已完成事实、未完成工作、计划和不确定结论。用户授权只能追溯到真实用户记录或实际审批事实，摘要自身不能新增授权。历史、工具原文和外部内容中的指令不会因被摘要而获得更高权限。

待摘要输入本身超限时，按可容纳的完整较早交互组分批形成中间摘要，阶段数必须有界且每批推进覆盖位置。中间摘要不成为可恢复的 CompactionEntry；全部完成并通过最终预算检查后才提交。若单条旧消息连同摘要指令也无法容纳，本期明确失败并保留历史，不静默字符截断。

### 4.4 提交、重复保护与失败

压缩按“选择范围 → 生成并校验摘要 → 检查新上下文预算 → 追加并同步 CompactionEntry → 更新恢复索引 → 切换模型上下文”推进。只有已持久化的有效压缩记录可以成为恢复起点；JSONL 已同步而索引更新失败时，压缩事实仍有效，允许使用内存结果继续并在后续重建索引。

重复保护以覆盖位置、有效消息进展及上下文版本为依据；时间戳只作辅助，不是唯一判据。没有新的可压缩消息时，不再次摘要同一内容或只摘要上一份摘要。新增用户输入或 Tool 结果后仍需重新检查预算，不能仅因最后一条 Assistant 的时间戳未变就跳过。

- 压缩成功：发布结果，自动继续原 Run，不要求用户再次确认或重新提交任务。
- 摘要请求失败、空摘要、格式校验失败、输出被上限截断或压缩后仍不满足预算：不提交 CompactionEntry，不修改原历史，当前 Run 以可理解失败结束。
- 用户取消：取消正在进行的摘要请求；未提交结果丢弃，已提交事实保留，原任务不继续。取消状态与持久化提交顺序必须一致。
- Provider 仍报告上下文超限：存在新增可压缩内容时，对同一有效上下文最多进行一次强制压缩恢复；再次超限或没有可压缩内容时结束，不能形成无限重试。
- 压缩与恢复不得重放已经执行的工具副作用。

### 4.5 Prompt 编排与缓存

固定系统指令、工具定义顺序和稳定工作区说明组成稳定前缀。摘要、保留用户原文和近期完整交互位于历史区域，保持确定的顺序、序列化和来源标识。每次调用时变化的时间、进度、用量和临时路径不插入稳定前缀。

提示词模板保存在 `prompts/`；预算、消息选择与运行时拼装由对应 Module 持有。已进入历史的工具预览不在每次请求前反复改写。压缩引起摘要变化时允许后续前缀失配；验收要求可解释且稳定的请求编排，不能承诺 Provider 必然命中缓存。

## 5. Session 格式、时间目录与恢复

### 5.1 按创建时间组织数据

默认数据根继续为 Anthias Project Root 下的 `data/conversation`，不由 Workspace 推导。`ANTHIAS_SESSION_DIR` 仍可覆盖 Session Directory，覆盖后沿用相同内部布局。

采用“UTC 创建日期 / UTC 创建时间戳＋Session ID / 会话内容”的结构：

```text
data/conversation/
├─ 2026-09-05/
│  ├─ 20260905T083015123Z-<session-id>/
│  │  ├─ session.jsonl
│  │  ├─ session.index.json
│  │  ├─ artifacts/
│  │  │  ├─ <artifact-id>.txt
│  │  │  └─ …
│  │  └─ migration-backup/             # 仅发生旧格式迁移时存在
│  └─ 20260905T101200456Z-<session-id>/
│     └─ …
├─ session-locations.json              # 可重建的 ID → 相对路径缓存
└─ .maintenance/                       # 锁、使用标记和清理恢复所需状态
```

日期和时间戳均从 Session Header 的 `createdAt` 得出，目录名不包含 Windows 不允许的冒号。Session ID 保证同一毫秒创建多个会话时仍不冲突。归档目录创建后保持稳定；重新打开、压缩或继续对话不会将其移动到当天目录。日期分层与 Session 独占目录共同避免把所有文件平铺在一个位置。

会话通过稳定 Session ID 打开，调用者不需要知道日期。Session Module 查找并校验定位缓存，失效时枚举合法日期目录和兼容的旧平铺记录，读取 Header 恢复映射。必须验证 Session ID、真实路径与数据根归属；多个互相冲突的有效来源不能靠“选择最新文件”消解。

定位缓存丢失不会新建同名空会话，也不会阻止恢复现存会话。锁与使用标记以稳定 Session ID 定位，不依赖正在迁移的会话目录；其具体文件结构在 Plan 中确定。

### 5.2 JSONL Schema 2

首行继续为不可变 Session Header，保存 `schemaVersion = 2`、Session ID、创建时间、规范化 Workspace 和 Shell。可变索引不写回首行。

每个 Entry 具有稳定 `entryId`、单调 `seq`、UTC 时间戳和 `parentEntryId`；首个 Entry 的父引用为空，属于 Run 的记录另带 `runId`。本期只写线性父子关系，保留稳定关联以支持后续演进，不实现分支选择或 fork 行为。

在已有消息、工具副作用开始和 Run 终态记录上，增加以下持久事实：

| 记录 | 必须表达的内容 |
| --- | --- |
| CompactionEntry | 摘要、覆盖截止 Entry、原文保留起点 `firstKeptEntryId`、额外用户原文引用 `retainedUserEntryIds`、压缩前用量及压缩后估算、关联模型/上下文版本 |
| 请求用量 | 调用用途、有效 usage 与其对应请求/历史位置，足以判断恢复后能否继续使用校准值；不保存 Provider 原始请求 |
| 审批决定 | 对应操作、模式、决定来源、结果及安全化理由、真实授权来源引用；能区分人工、自动审核和确定性策略 |
| 会话使用 | 成功打开等无法从业务消息直接推导的真实使用事实，用于恢复最近使用时间 |
| 工具产物引用 | 所属 ToolCall、产物 ID、类型、存储字节量、完整性与有界预览；必要时包含不完整原因 |

本期不持久化流式 delta、自动审核内部推理或完整审核输入，不因新增记录而把提示词、Model Stream 或 Provider 类型暴露给 TUI。

### 5.3 历史读取与模型恢复分开

历史读取返回用户与 Assistant 已保存的消息和可展示的压缩事实；压缩前原文继续存在。模型恢复则使用最新有效 CompactionEntry、额外保留用户消息、保留尾部及压缩后的新增消息，形成较小上下文。读取了历史不意味着将其全部发送给模型。

`session.index.json` 至少记录：

- 对应 Session、Schema、已校验的日志长度/尾部位置等有效性信息。
- 最新有效 CompactionEntry 的 Entry ID 与 UTF-8 字节偏移。
- 原文保留起点的 Entry ID 与 UTF-8 字节偏移。
- 尾部之外保留的用户 Entry 引用及相应字节偏移。
- 构造恢复路径所需的末尾进展信息。

偏移以磁盘字节计算，不以 JavaScript 字符数或行号代替。保留尾部通常位于 CompactionEntry 之前，恢复时必须读到这部分，不能只从压缩行向后读。额外用户引用与尾部重叠时只加载一次。

索引采用临时文件写入后替换。丢失、陈旧、截断或与 JSONL 不一致时，校验日志并重建；不能根据索引中的孤立记录跳过日志有效性判断。索引最后位置后的新增记录必须继续读取。压缩记录无效时退回前一个有效恢复点或原始历史，既有未完成 Run 和未知工具结果继续按原有恢复语义处理，不执行副作用重放。

### 5.4 旧会话迁移

识别现有 `<session-id>.jsonl` 平铺格式。迁移仅针对用户显式打开的会话，在下一次写入前完成，不在后台批量改写全部旧会话。成功打开需要记录使用事实，因此旧会话的正常打开会在写入该事实前触发迁移；只读扫描和校验不会触发迁移或刷新使用时间。

格式转换与目录迁移作为一次可恢复操作处理：取得该 Session 的必要互斥，保留原始日志的完整备份，转换为 Schema 2 临时文件，校验消息、顺序、Workspace、Shell 与恢复状态，再发布新目录和定位缓存。原始 Entry ID、序号、时间戳及用户内容保持不变，父引用按原有顺序补齐。

迁移不得执行旧工具、伪造完成记录或把迁移时间当作创建时间。失败和进程中断后，至少保留一份可恢复的原始会话；临时产物不能被当成新的独立 Session。出现无法确认权威来源的冲突时明确报错并保留数据。已知存活的旧写入者存在时拒绝迁移，不支持新旧版本并发写入同一 Session。

迁移备份与新 Session 共同归属一个目录，随该会话到期清理。本文不授权扫描或迁移其他 Workspace 下未配置为当前 Session Directory 的旧数据。

## 6. 工具输出与产物访问

### 6.1 有界结果与持久原文

- 先按单工具与同批合计预算分配预览，再形成持久 ToolResultMessage。同批结果按 ToolCall 来源顺序确定分配，不能因并发完成次序不同而挤占预算。
- 原文需要因上述任一预算被缩减时，必须提供对应产物或明确说明原文保存失败。多个分别不超单工具上限的结果，也可能因合计预算需要落盘。
- 持久预览包含成功/失败/拒绝/取消等原始结果状态、必要错误与关键输出、是否截断，以及产物 ID 和访问方式。不能让“执行成功”掩盖“原文不完整”。
- Tool 以流式方式写产物并收集有界预览，不能先把全部命令输出保存在内存再决定落盘。并发写入必须共同计入 Session 磁盘预算。
- 命令达到产物上限或磁盘写入失败后，继续排空输出管道，避免阻塞子进程；引用明确说明截断、磁盘不足或写入失败。取消仍按命令终止合同执行。
- 产物文件成功持久化后，才提交声称可读取的引用。进程中断产生的半成品只能按已验证的实际完整性恢复，不能伪称完整。
- Tool 的流式事件与 TUI 详情同样保持有界，不把完整大文件重新积累在渲染内存。已有字节和行数保护继续作为内存及终端输出的辅助上限。
- API Key 等已知敏感配置不进入产物、JSONL、审核记录或终端文本；继续沿用命令环境收敛和敏感错误安全化。

### 6.2 专用只读 Tool

增加一个产物读取 Tool，提供按行分页读取和字面文本搜索；返回内容也受到普通工具结果预算约束。查询结果优先分页和提供继续位置，不把读取产物的结果再次递归写成新产物。

单行超过返回预算时必须支持行内继续位置，不能跳到下一行而丢失余下内容。分页和搜索均返回能继续前进的游标，续读不重复或遗漏已截开的内容，不切断 UTF-8 字符；搜索可返回命中附近的有界片段及来源位置，不能把未扫描部分声称为无匹配。具体游标字段在 Plan 中固定。

模型使用产物 ID 调用，不能提供任意绝对路径访问磁盘。访问限于当前 Session 已引用的产物；Session Module 校验归属、路径和文件身份，不跟随逃逸到归属目录之外的链接。产物缺失、未保存完整或引用失效时返回明确结果，禁止重新执行原命令来补造输出。

该 Tool 属于只读能力，在 Plan 模式下也可使用。它不扩大现有 `read_file` 的 Workspace 权限范围。产物引用提供可理解的大小、完整性与访问方法；TUI 通过 Agent 提供的数据展示引用，不直接绕过 Agent 读取数据根。

## 7. AutoAllow 自主审批

### 7.1 模式与决策流程

增加 `auto_allow` 权限模式，TUI 显示为 AutoAllow，CLI 使用 `--mode auto_allow`。保留 Agent / Plan 的既有行为，新启动进程仍默认 Agent；模式只在空闲时切换，历史中的模式不自动成为本进程的新授权。

| 判断结果 | AutoAllow 行为 |
| --- | --- |
| 确定性策略已允许 | 直接执行，保留应有的事实记录 |
| 明确禁止的操作 | 拒绝，模型或用户选择模式都不能绕过硬禁止规则 |
| 需要审批且已有足够用户授权 | 交独立审核调用判断，批准后继续 |
| 缺少授权、目标影响不清楚或审核不能完成 | 向用户展示具体操作、影响和原因，进入现有人工确认流程 |

高风险不等于每次重新询问：已有明确且足够的任务授权可以支持自动批准。主 Agent 提交工具请求或声称“用户已经授权”，本身不构成授权；独立审核必须能检查真实用户消息、实际审批事实及相关任务进展。

### 7.2 独立审核调用

审核使用当前配置模型的独立、受限上下文，不继承主 Agent 的工具执行权，不调用 Tool，不将审核输出作为普通 Assistant 回复。输入包含待执行动作的精确内容、规范化目标、Workspace/Shell 等必要执行条件，以及有出处的用户授权和相关上下文。

审核返回可校验的允许或拒绝结果、风险判断与简短理由。审核明确拒绝但未触发确定性硬禁止时，带审核理由转入人工确认；输入不足、模型失败、结果格式错误、输出截断或无法确认授权时也不自动放行，转入人工确认。用户最终拒绝则结束本次工具调用并记录拒绝结果。确定性禁止仍优先，不能把硬禁止操作交人工兜底后执行。

预算内无法完整放入待执行命令、文件变更及必要目标信息时，不截取动作进行审核。可以减少无关历史，授权信息仍不足则转人工。摘要和工具内容中的自我授权不算依据，压缩恢复后仍可按引用读取所需的真实授权记录。

审核最多对同一待执行动作自动请求一次，失败或拒绝后不反复调用同一审核等待放行。用户提供新的有效授权或动作发生实质变化后，按新的审批处理。

### 7.3 执行绑定、审计与取消

批准绑定本次准备完成的具体操作及目标。命令、工作目录、目标文件或待写内容发生变化时，旧批准失效；必须重新准备并判断。批准结果不自动扩展为以后所有同类命令的许可。

人工、自动审核和确定性策略的许可来源都可记录。任何需要记录开始事实的副作用，在执行前必须成功持久化相应决定和 ToolExecutionStartedEntry；不能继续以“是否有人工作出的 approval ID”决定要不要记录开始事实。审批相关存储失败时不执行动作。

用户取消审核、等待人工确认或整个 Run 时，迟到的批准不能启动工具。TUI 显示正在审核、已自动批准、转人工或已拒绝的状态及简短原因；记录中不得假称用户手动批准，也不展示审核模型的内部推理。

AutoAllow 是应用层审批能力，当前工具仍以本地用户权限执行；本 Feature 不新增 OS 沙箱或独立多 Agent 工作流。

## 8. 两周保留与启动清理

### 8.1 使用时间与范围

Session 创建、成功打开、接受用户输入、产生真实 Assistant/Tool 消息及 Run 结果属于使用活动。成功打开等独立活动写入会话使用记录，其余活动可由相应 Entry 推导。`lastActivityAt` 取有效使用事实的最新时间，允许索引缓存但必须可从日志恢复。

目录创建时间、文件 mtime、索引更新、只读扫描、迁移和整理缓存都不能刷新使用时间。没有使用记录的旧 Session 从有效 Header、消息和 Run 时间推导；无法可靠判断时跳过清理并报告原因，不猜测为过期。

当 `当前 UTC 时间 - lastActivityAt >= 14 × 24 小时`，且没有存活或状态不明的使用者时，会话具备清理资格。目录日期不参与这一判断，系统时钟异常导致时间在未来时同样跳过。

清理范围是该 Session 的日志、索引、产物、迁移备份及归属的临时文件。全局定位缓存同步移除对应项，空日期目录可移除。Workspace 文件、模型配置以及归属不明的目录不属于清理对象。

### 8.2 打开保护与并发

Agent 从成功打开 Session 到显式关闭期间持有使用标记，覆盖空闲、浏览、压缩、审核和执行阶段。现有 Run 独占锁继续保护写入，但不能代替打开期间的使用标记。

打开、迁移、写入和删除必须按同一 Session ID 协调。清理方在取得必要互斥后，再次检查使用标记、日志进展和过期时间，不能根据扫描时的旧结果直接删除。多个进程打开同一会话时，各自的使用标记必须有独立所有者；只能释放自己的标记。确认进程死亡后才回收残留标记，无法确认存活状态时保留数据。

其他进程仅追加会话使用记录时，不使当前 Agent 的业务历史失效。当前 Agent 在取得写锁后校验这些记录，刷新日志位置、序号和父引用，继续使用未变化的模型上下文。新增消息、CompactionEntry 或影响执行恢复的事实则仍按历史变化处理，拒绝用旧上下文开始下一 Run 并提示重开；不能把所有日志长度变化一概当成业务历史改变，也不能忽略真实变化。

会话被声明进入删除阶段后，新的打开请求不得读到部分内容或新建同 ID 空会话，而应返回明确结果。删除中断保留可识别的清理状态，在本轮或下次启动继续；该中间状态不作为正常会话展示。

### 8.3 后台进程

每次生产启动触发一个短生命周期清理子进程。多个 Anthias 同时启动时，同一数据根只允许一个清理任务实际运行。主 TUI 不等待全目录扫描；Windows 隐藏子进程窗口，普通交互无需手动确认清理。

单次工作必须有时间和扫描范围上限，保存必要的继续位置，避免每次只重复扫描同一批会话。到达上限、完成或取消时退出；异常留下明确结果及可恢复进度，下次启动继续。具体运行上限在 Plan 中确定，不引入常驻调度服务。

清理发生在过期后的下一次启动，不承诺第十四天定点删除。删除前校验真实路径仍在受管数据根内，不遍历逃逸的符号链接或 Windows junction。清理失败不阻止正常使用未受影响的会话；TUI 仅展示有意义的清理结果或异常，不为扫描过程持续刷屏。

代码目录与运行数据目录分别遵循本节和第 5.1 节。当前文档阶段只创建 Spec；其余源文件在获准实施的对应 Plan 中实际迁移或实现，不提前建立空文件。Plan、Tasks 和 Report 也按项目流程进入对应阶段后创建。

### 9.4 Agent Interface

Agent Interface 继续提供 state、prompt、abort、subscribe、模式切换及人工审批响应。为完整释放 Session 使用标记，增加幂等的关闭行为：关闭后拒绝新 prompt，取消并收敛未完成工作、刷新必要事实、释放自身持有的资源。TUI 退出必须调用该行为；不得自行修改 Session 锁文件。

AgentEvent 增加压缩开始/结果、自动审核阶段与结果，以及可安全展示的上下文占用信息。必须保持同一 Run 的有序发布和单一终态；压缩或审核成功不等于 Run 已完成。若用量来自估算，TUI 明确标注，未返回缓存信息时不显示虚假的零命中率。

## 10. 已确认决定与不在范围内

本稿收录的核心决定为：每次模型发送前检查；预留 20k 安全余量及摘要输出；有效 usage 优先、缺失时估算；用户原文优先保留；成功压缩自动继续；历史与模型上下文分离；JSONL 事实源及旁路索引；按创建时间组织独占 Session 目录；工具原文按 Session 归属；AutoAllow 独立审核；两周未使用会话在启动时清理。

本 Feature 不包含：

- 可使用的对话 fork、执行分叉、工作区快照、Git worktree 隔离或分支比较界面。
- OS 沙箱、低权限账户、网络代理、多 Agent 任务分派或审批模型的工具执行权限。
- 多 Provider 框架、独立模型切换产品流程、云端会话同步、向量数据库或跨会话长期记忆。
- 无上限保留用户原文、工具原文或 Reasoning；对所有模型完全精确的本地 token 计算；保证缓存命中。
- 常驻定时服务、回收站恢复产品、批量改写未打开的旧 Session、清理 Workspace 文件。
- 新建 Desktop、Host、RPC 协议、通用 Prompt 框架或独立 Session 管理 UI。

## 11. 验收标准与验证边界

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| AC-01 | 已知模型与未知自定义模型启动 | 已知模型自动取得能力和应用余量；未知容量得到准确配置提示，无模型名字猜测 |
| AC-02 | usage 完整、缺失、含缓存以及压缩后校准 | 输入/输出/缓存语义正确，未知不记零，新输入被计入，变化后的请求不误用旧锚点 |
| AC-03 | 中文、英文、工具定义及消息结构增加 | 全请求估算包含这些内容，TUI 区分估算与实际；不只计算用户正文 |
| AC-04 | 阈值前、恰好达到阈值及 Tool Loop 内跨过阈值 | 每次普通调用前检查，达到阈值先压缩，普通和摘要输出空间分别满足约束 |
| AC-05 | 长 Run、多个 ToolCall 与多次用户纠正 | 完整保留最新请求，优先保留用户原文，调用与结果成组，较早已完成片段可压缩 |
| AC-06 | 压缩成功、失败、截断、取消及提交后索引写失败 | 成功自动继续；失败不覆盖历史；取消不继续；已同步的压缩不因缓存写失败丢失 |
| AC-07 | 相同内容再次检查或 Provider 超限 | 不重复摘要自身，不无限重试；有新增用户或工具内容时重新判断 |
| AC-08 | 稳定请求连续发送及压缩发生 | 稳定前缀和工具定义顺序一致，变化位于约定区域，不声称必然缓存命中 |
| AC-09 | 同日、跨 UTC 日期、同毫秒创建以及重新打开 | 使用日期与时间戳目录，ID 不冲突；再次使用不移动目录，仍可按 ID 打开 |
| AC-10 | 两种索引丢失、陈旧、损坏或日志尾部新增 | 能校验事实并恢复，中文字节偏移准确，压缩前保留尾部与额外用户原文无遗漏或重复 |
| AC-11 | 读取完整历史与实际模型请求 | 历史保留，模型只收到有效摘要和选中内容；恢复不重放工具副作用 |
| AC-12 | Schema 1 显式打开迁移及中断 | 消息和标识保留、备份存在；半成品不变成第二个 Session，失败后仍有可恢复来源 |
| AC-13 | 单工具超限与多个工具合计超限 | 预览和内存有界，必要原文落盘，并发结束顺序不改变预算归属 |
| AC-14 | 达到单产物/Session 磁盘上限或写入失败 | 继续排空命令输出、标记真实完整性，不生成声称完整可读的假引用 |
| AC-15 | 产物分页、搜索、超长单行、缺失及跨 Session 访问 | 当前 Session 内按预算读取，行内游标持续前进且不丢内容；越权拒绝，缺失不重跑原命令，结果不递归落盘 |
| AC-16 | Agent / Plan / AutoAllow 切换与重开 | 旧模式行为保留，空闲切换，新进程默认 Agent，Plan 可读取当前会话产物 |
| AC-17 | 已授权动作、高风险已充分授权、授权不足与硬禁止 | 常规操作顺畅推进；自动审核依据真实授权；不足转人工；硬禁止仍拒绝 |
| AC-18 | 审核失败、格式错误、截断、拒绝及迟到批准 | 不自动执行或无限重审；非硬禁止的审核拒绝转人工；取消后迟到批准无效，TUI 正确呈现来源和原因 |
| AC-19 | 批准后动作改变或持久化失败 | 旧批准失效或拒绝执行；自动与人工许可都先记录必要副作用开始事实 |
| AC-20 | 过期、刚使用、当前打开但空闲、使用标记状态不明 | 只清理可确认过期且未使用的 Session；真实打开刷新使用时间，缓存维护不刷新 |
| AC-21 | 打开/写入/迁移与清理并发、多个应用同时启动 | 活动会话受保护；仅新增使用记录不误报业务变化，真实变化仍拒绝旧上下文；同根单一清理，不出现部分读取或同 ID 空会话 |
| AC-22 | 清理中断、路径逃逸、时间异常和未知归属目录 | 路径校验生效，异常跳过或恢复重试，Workspace 和其他归属数据不被删除 |
| AC-23 | TTY、非 TTY、窄终端以及 Agent 关闭 | 压缩与审批过程可理解；顺序和单一终态保持；退出释放 Session 使用标记及未完成资源 |
| AC-24 | 目标目录、生产调用链与公开出口 | 按第 9 节组织实现，迁移后真实生产路径可用；TUI 只通过 Agent，内部模型与存储合同不外泄，不遗留平行旧实现 |

验证优先通过已有 Agent Interface、内部可注入 Model Stream、临时 Session 文件和实际 TUI 入口完成，使用确定性本地响应覆盖主流程、失败与竞态。模型内部合同不为测试从 package 入口导出；不为文件移动重复编写实现镜像测试。

实施 Plan 应给出与当前增量对应的精确验证命令，沿用项目 `pnpm check`、`pnpm test` / `pnpm verify` 门禁。文档阶段只校验结构、链接和合同一致性，不以未运行的测试作为结果。真实 Provider 的 token 偏差、摘要质量、审核表现及缓存命中另行取得授权验证；本地确定性验证不等于这些外部效果已成立。
