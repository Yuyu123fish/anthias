## 2. Plan 01：Session 与工具产物生命周期

生产装配进入 `startup.ts`，Agent 工厂持有 Session、Run 与清理资源，`agent-loop.ts` 推进 Model / Tool / Model。TUI 通过同一个 Agent Interface 输入、展示与关闭。

Session 按 UTC 创建日期与时间戳归档，稳定 ID 通过可重建的定位缓存查找。Schema 2 保留线性父引用；显式打开 Schema 1 时保存原始字节备份并迁移，发布中断后仍能确认权威来源。仅其他打开者追加使用事实时刷新存储检查点，新增业务事实继续拒绝旧上下文。每个打开者独立持有使用标记，空闲查看期间也受保护。

工具原文流式写入当前 Session 的产物目录，预览受单项 4,000 / 同批 8,000 token 限制，按实际调用数预分额度。可大输出 Tool 的非空原文统一保留，元信息先于正文分配；读取分页按真实结果额度推进游标，不能越过未展示内容。产物磁盘限额为单项 32 MiB / Session 256 MiB；达到上限或磁盘写入失败仍排空命令输出，执行状态与原文完整性分别表达。只有持久消息中的引用能够通过 `read_artifact` 分页或搜索，长行游标保证前进，读取不重新执行原命令。

启动时由短命子进程检查过期会话，最多检查 200 个候选、运行 30 秒；JSONL 超过 64 MiB 时本轮跳过并说明读取预算限制。真实活动超过 14 天且没有存活或状态不明的使用者时，先写删除意图，再将独占会话目录移入受管隔离目录并删除。维护不刷新使用时间，来源冲突、异常时间和链接归属不明时保留数据。

`Agent.close()` 幂等地拒绝新输入、取消并等待当前请求、关闭产物与 Session，最后收敛其清理工作者。TUI 退出等待该结果；退出等待期间重新持有子进程句柄，避免 Node 在顶层异步关闭尚未完成时提前退出。

## 4. Plan 02：上下文预算与自动压缩

模型文件进入 model/，通用 Adapter 在每次请求显式设置输出上限；内置能力只提供配置数据，不产生模型专用调用分支。已知 DeepSeek V4 Flash 自动提供窗口，未知模型要求 ANTHIAS_MODEL_CONTEXT_WINDOW；安全余量固定 20,000。普通回复、摘要、保留原文的默认策略分别为 16,000 / 8,000 / 32,000，可通过 Plan 02 中的环境变量调整。

每次 Model 调用前，Context 对固定指令、工具 Schema 和实际重发内容执行预算检查，包括同一 Run 内 Tool 返回后的请求。有效 usage 优先校准，消息前缀、模型、摘要、Schema 或临时 Reasoning 改变时不复用旧锚点。缓存计入输入子集；缺失用量保持未知，回复/摘要/审批累计统计分开。/context 展示详细用量，底栏显示当前窗口占用。

完整历史与模型发送投影分开。选择器优先保留真实用户原文，保证最新用户输入与完整 ToolCall/结果组；摘要只消费上一摘要和本次退出原文区的完整片段。最多八次有界中间摘要，验证栏目、终态、大小和剩余容量后才持久写入最终 checkpoint，再自动继续。取消、失败、无进展和超限重试上限均保留原始历史。恢复重建投影并去重；usage/compaction/approval 的 lease 写入具备 Run 归属。

## 5. Plan 03：AutoAllow 自主审批

新增 auto_allow，CLI 使用 --mode auto_allow，TUI 使用 /mode auto_allow。默认启动仍为 Agent，模式只在空闲时切换。已有 Plan 只读策略保留，read_artifact 也受当前 Session 引用约束。

确定性策略先判断硬拒绝；需要审批的动作由同一模型进行一次独立审核。请求不携带工具，输入最多 8,000 token、输出 2,000 token，并检查窗口与已声明输出能力。完整动作不能纳入预算，或没有可完整核验的近期授权时直接转人工。真实 User 与带具体绑定的人工批准才可成为来源；摘要、Assistant 自述、工具输出以及自动批准都不能增加授权。

动作指纹绑定准备好的文件内容、目标身份或命令、Shell、cwd 和超时。命令在 spawn 前复核 cwd 的真实路径及目录身份，文件沿用执行前内容/身份复核。改变后拒绝执行旧动作，必须通过新 ToolCall 重新准备。审核异常、截断、非硬拒绝和引用无效转人工；取消后不接受迟到批准。

人工、自动与确定性策略的副作用允许决定统一先持久化，再保存 ToolExecutionStartedEntry，成功后才执行。新的审批记录可校验动作指纹、来源引用和批准标识；旧格式继续兼容。审批存储失败时停止 Run，不执行动作。TUI 呈现正在审核、自动批准、转人工及决定来源，审核 Reasoning 不进入主对话。

### 真实模型证据

2026-09-05 通过确定性主循环请求一次临时文件写入，独立审核实际调用 deepseek-v4-flash。审核返回 stop，输入 769 / 输出 73 token，缓存读取为 0，缓存写入未知。结果来源为 auto_review，decision=allowed，审批记录先于执行开始，临时文件内容与授权一致，没有人工降级。

这是一条“确定性动作选择 + 真实独立审核 + 真实临时文件执行”的混合验证。它证明审核生产 Adapter 和执行顺序可用，不等于完整自由编码任务、安全审核准确率或高风险指令识别率已经验收。当前仍无 OS 沙箱。
