# Feature 015：执行恢复与输入中断

状态：已实现

## 开发者速览
> **一句话**：工作区受阻时能够说明原因、停止和恢复，用户能够立即中断回答并处理排队消息。<br>
> **核心做法**：显式阻塞、有限恢复、同一输入身份与必要清理顺序。<br>
> **边界**：复用现有 Module，只保存已发生的阻塞，不建设后台资源管理平台。<br>
> **风险 / 未验证**：外部 CLI 的 Windows 句柄问题不在本次实现范围；真实 Provider 未验证。<br>
> **当前 / 请审阅**：已按职责纠正完成实现和验证，证据见 Report，等待验收。

## 问题

[2026-09-11 事故](../../docs/incident/2026-09-11-multi-agent-workspace-blocking.md) 中，命令清理不明后保留独占锁，后续操作持续等待，根缺少故障原因。运行中输入默认 steer，不能满足 Enter 排队、Esc 立即打断的目标。实际输出预算偏低、协作结果冗长、文件写入不返回新版本，进一步增加失败与重复工作。

## 用户流程与行为

1. 工作区正常时保留现有文件版本、权限与排他规则。命令 timeoutMs 仍表示执行超时；取锁另以同一数值为等待上限，两者分别计时，取消始终有效。
2. 命令清理不明时形成带唯一 blockId、工作区、所属 Session、ToolCall、原因和时间的阻塞。已排队及新到达的相关写入明确失败，不启动进程或修改文件。模型、组内通信、直接状态与停止仍可用。
3. 根和用户可查询并请求有界恢复，成员不能解除其他操作的保护。运行时只重查本命令持有的资源；确认清理完成才解除对应阻塞。不确定时保持阻塞；用户可在外部清理后通过明确的直接确认解除，保留用户确认来源，模型不能伪造该确认。
4. 仅将已产生的阻塞保存到受管数据目录。重启打开相关工作区时先恢复这些阻塞；没有存活资源句柄时不凭裸 PID 清理。保存失败不能放开写入，并明确说明跨重启状态未保存。未落盘的崩溃不作完整恢复保证。
5. 恢复匹配当前 blockId，迟到结果不能解除新阻塞；恢复不会自动重放副作用。恢复中的资源检查有截止时间，且不等待被阻塞的写锁。
6. 运行中 Enter 默认 followUp，空闲 Enter 立即开始。接受的输入显示排队状态；有待处理用户消息时 Esc 提升最早一条输入，沿用 inputId，不重新发送正文。重复 Esc 幂等，未提交草稿不自动发送。
7. Esc 立即取消根当前模型、所属工具、批准与资源等待；保留成功结果，补齐未执行和未完成调用的准确结果，等待本 Run 必要清理后结束旧 Run，再处理该输入。其他成员不因 Esc 自动暂停，原群组截止时间不重置。
8. 清理不明时结束旧 Run 的执行生命周期，输入保持待恢复，不标为已消费。状态、停止和恢复通过现有直接控制入口可用。用户停止高于迟到恢复；Ctrl+C 停止群组并暂停输入，无排队消息时 Esc 保留界面取消行为。
9. 输入领取、持久化和消费具有明确顺序；正在持久化的输入不能因 Esc 再领取，取消后成功写入历史的输入不重复执行。
10. 成员的清理不明、工作区阻塞和输出超限对根可见；agent_wait 因新故障提前返回。列表和等待默认紧凑快照，完整任务按需查询，复用已有事件和协作路径。
11. 成功 write_file/edit_file 返回实际提交字节的新版本。原有过期版本拒绝、锁内核验及原子替换保留。
12. 核对 deepseek-flash 能力、配置来源和实际预算；普通 Coding 默认 64,000，受已核验模型能力与窗口约束，摘要和审核独立。展示安全的生效配置，记录请求采用预算。修正本地旧预算只变更相关非敏感配置，保留凭据及其他自定义内容。

## 实施边界

不新增控制调度框架、完整命令恢复日志、跨进程资源接管、自动崩溃恢复、通用后台任务管理或协作增量同步协议。不得把输出 Done、停止、关闭成员或重启当作清理证明。恢复不绕过现有根/成员权限，不提供模型可调用的无条件解锁。

保持 Feature 014 的十个并发、根管理成员、默认共享工作区、显式 worktree 和三种权限模式。仅根输入中断使用独立取消原因，既有用户停止、失败和关闭仍执行原有群组收束。

## 验收

- 同工作区命令清理不明后，排队与新写入快速返回相同阻塞来源，无实际副作用；其他工作区可继续。
- 自动检查失败保持阻塞、成功仅解除对应记录；重启载入、用户直接确认和保存失败均有明确结果。
- 等待超时与执行超时可区分，等待取消不启动进程，正常输出与进程清理保持原有结果。
- Enter、Esc、重复 Esc、消费持久化竞争、停止/继续/再停止覆盖模型、工具和资源等待，成功工具不重放。
- 根能及时得到故障摘要，紧凑输出不携带完整成员任务；编辑成功返回的版本可继续用于下一次修改。
- 配置来源与请求预算可核对，真实凭据不进入日志、文档或测试。
- 通过必要定向测试、静态/类型检查与最终整体回归；事故记录和 Report 区分本地验证、真实浏览器与真实 Provider 边界。

## 2026-09-12 后续修复合同（职责纠正）

开发者明确指出浏览器控制属于外部工具，并要求先纠正方案再修改。以下合同替换上一版浏览器专用适配方案；本增量连续完成，不新增 Feature，不提交、不推送。

| 责任 | Anthias 项目内 | 外部工具负责 |
| --- | --- | --- |
| 命令执行 | 固定 Shell、cwd、权限、工作区协调、有界输出、超时与取消 | 命令本身的业务语义和参数解析 |
| 资源生命周期 | 观察自己启动的命令进程及输出流；保留当前持有关系，按通用执行协议取消或重查 | 浏览器 daemon、session、namespace、profile、CDP、页面与截图的管理 |
| 故障恢复 | 记录阻塞与来源；有界重查原命令资源；有证据才解除对应保护 | 工具内部故障修复、内部协议和关闭命令的实现 |
| 能力接入 | 按既有权限调用 CLI/MCP；Skill 可说明外部工具的使用方法 | 具体浏览器控制能力及平台兼容实现 |

Anthias 不根据可执行文件名称或参数内容识别浏览器，不改写 agent-browser 命令，不内置浏览器代理、私有 IPC、CLI 参数规则或自动 close；Session 也不拥有浏览器专用配置和生命周期。

保留并完成以下通用修复：

- 分别保存进程退出、stdout/stderr 自然结束和命令收尾。主进程退出但输出迟迟未结束时，短宽限后报告 output_pending；不能耗尽完整执行预算，也不能当作成功直接释放写入保护。
- 收尾只移除本模块的监听，保留 Node 内部生成 close 事件所需的监听。后台资源自然结束后能够用新证据恢复，历史清理失败不得永久否决恢复。
- 恢复仅针对当前仍持有的命令资源，接受独立取消信号和截止时间，不等待被阻塞的写锁，不接受任意清理 Shell 字符串或孤立 PID。命令进程退出后不得再按该 PID 终止未知后台资源。
- 无法确认资源已清理时继续阻塞。外部程序仍持有句柄、资源归属丢失或应用重启后没有原句柄时，不承诺自动恢复；外部工具或用户清理后，再重查或由用户直接确认。普通对话“已清理”不能代替 /agent recover <blockId> confirm-cleanup。
- 原故障现场已按用户委托完成的外部清理及 .resolved 记录保留。这是一次有证据的人工委托操作，不成为 Anthias 内置浏览器能力。

本次不修复 agent-browser 自身的 Windows daemon/句柄继承，也不更改全局 CLI、MCP 或 Skill，不扩建通用后台任务平台。原 PowerShell 管道组合仍可能受到外部 CLI 行为影响；报告必须明确区分 Anthias 恢复缺陷与外部命令缺陷。

验收：源码与构建产物不再含浏览器专用运行时；保留权限、写锁、输入中断和阻塞记录；真实 Node 管道迟到结束后能恢复；主进程退出但输出未结束时有界失败且不错误解锁；静态/类型/构建与完整回归通过。验证不启动浏览器或调用真实 Provider。
