# Feature 015 实施计划

状态：已实现

## 开发者速览
> **一句话**：在现有命令、工作区协调与 Session 输入上完成一次恢复闭环。<br>
> **核心做法**：先定向复现，再按资源恢复、输入中断、配置反馈的依赖顺序修改。<br>
> **边界**：单一 Plan，不引入新的运行平台或控制调度器。<br>
> **风险 / 未验证**：Windows 子进程生命周期需保留清理不明边界，外部资源不凭猜测接管。<br>
> **当前 / 请审阅**：单一 Plan 已完成，最终证据见 Report。

## 基线与范围

基线 21e92ba，当前分支 codex/feature014-unified-multi-agent。保留 README 的事故入口、docs/incident 和 agent-loop.ts 已有用户注释。只修改本 Feature 所需代码与文档；不提交、不推送。

## 实施步骤

1. 用已有命令/工作区测试入口复现“清理不明后排队无法结束”。工作区协调 Module 增加阻塞、有限恢复与仅阻塞持久化；命令层提供准确资源结果，分别计算取锁和执行时间。
2. 复用直接控制接入状态、恢复、用户确认；根快照和等待反映故障。确保不依赖新模型 Run 或被阻塞的锁。
3. SessionAgent 管理输入领取、立即取消、清理与后续 Run；根输入中断不停止成员。TUI 用 inputId 呈现队列，Esc 发起提升，Ctrl+C 仍停止群组。
4. 文件工具返回提交版本；协作工具缩小默认快照。核对模型能力和非敏感配置，公开安全预算信息，保持摘要/审核独立。
5. 定向验证后执行完整门禁，进行一次对照 Spec 的最终检查。更新 Report、Tasks、事故记录、Quick Start 与受影响稳定文档。

## 验证

优先扩展现有 workspace-concurrency、command-tool-loop、session-input-flow、agent-controls、multi-agent 和 TUI 测试中的必要路径。模拟子进程与确定性模型验证取消、顺序、故障和恢复；不为内部方法逐个建重复用例。

最终执行 corepack pnpm verify。中间构建和定向测试只在改动影响相应路径时运行。真实 Provider 不调用；浏览器问题先使用本地最小进程/管道复现，不操作原用户产物或保留后台进程。

## 风险与停止条件

遇到超出 Spec 的公开行为、额外外部状态变更或不可证明的资源所有权，保留明确失败而不放宽保护。记录无法验证的浏览器初始原因，不以模拟测试冒充原环境验证。既有不相关修改不清理、不覆盖。
