# Feature 015 实施报告

状态：已实现

## 开发者速览
> **一句话**：清理不明有明确恢复入口，用户可以用 Esc 中断回答并处理排队消息。<br>
> **核心做法**：阻塞持有写入保护，输入沿用同一身份，配置与故障提供实际证据。<br>
> **边界**：仅保存已发生的阻塞，复用现有协作与 Session 生命周期。<br>
> **风险 / 未验证**：浏览器命令退出异常仍可复现；没有调用真实 Provider。<br>
> **当前 / 请审阅**：完整门禁通过，等待开发者验收；按开发者后续授权保存一次本地提交。

## 交付结果

先保存 [Spec](spec.md)、[Plan](plan.md) 与 [Tasks](tasks.md)，再按开发者授权连续完成一个增量。基线为 `21e92ba`，在已有分支 `codex/feature014-unified-multi-agent` 实施；保留原有 `agent-loop.ts` 注释及事故文档改动。

- 命令清理不明后，显式阻塞记录接管保护。已经排队与新到达的相关文件、命令和 Git 写入不再无声等待，返回来源与 blockId。
- `/agents` 查看阻塞；根可以调用 `agent_recover_workspace`，用户可以直接调用 `/agent recover <blockId>`。恢复只检查原资源，不重放工具。
- 原资源仍无法核实时，用户外部清理后可直接输入 `/agent recover <blockId> confirm-cleanup`。模型工具不能携带这项确认，成员不能取得根恢复权限。
- Enter 默认 followUp。Esc 从两个输入队列选出接收最早、尚未领取的用户输入，沿用 inputId，立即取消当前回答；必要清理完成后再消费。重复 Esc 不再发布重复排队事件或复制消息。
- 输入中断仅影响根当前 Run。Ctrl+C 仍停止群组；停止/继续/再次停止中，以最后一次明确停止为准。清理不明时输入保留，后续恢复不能覆盖用户停止。
- 根默认获取紧凑成员状态、结果摘要与新故障；完整任务和历史按需查询。相同故障在新 Run 中再次发生仍能唤醒 agent_wait。
- 文件成功原子替换后返回实际 UTF-8 字节的 SHA-256 newVersion，原有 expectedVersion 和锁内校验保持。
- deepseek-flash 及兼容别名使用已核验能力数据；`/diagnostics` 提供安全生效配置及来源，request_usage 保存生产 Adapter 实际采用的输出预算与推理强度。

## 入口与职责

| 行为 | 调用链与职责 |
| --- | --- |
| 命令与写入保护 | executePreparedCommand → workspace-access：取锁时冻结真实资源键；执行清理不明后安装阻塞，再结束普通租约。路径损坏不破坏保护移交。 |
| 持久阻塞与恢复 | workspace-access 保存 workspace-blocks 中的阻塞事实；加载失败关闭写入。恢复核对 blockId、原资源和调用者来源，持久化解除依据后移除阻塞。 |
| 根与直接控制 | multi-agent/index 绑定根权限与工作区可见范围；TUI 复用 collaboration.execute，不经新模型 Run 或被阻塞的写锁。 |
| 输入中断 | TUI Esc → Agent.interruptForInput → SessionAgent 取消、清理、Run 封口、消费同一输入；本 Run 的工具结束事件绑定具体 blockId。 |
| 故障反馈 | members 维护新故障序号，wait 在新故障时返回；runtime 把有限诊断事实提供给根后续请求，不赋予额外权限。 |
| 配置诊断 | local-config 只统计允许公开的字段来源；startup 生成安全摘要；生产 Model Adapter 报告实际采用参数，Context 随用量写入 Session。 |

没有新增控制调度器、后台资源管理平台、跨进程接管或协作差量协议。独占租约与阻塞由原工作区协调 Module 持有；阻塞只包含已观察到的清理不明事实。

## 顺序与失败边界

命令 timeoutMs 保留执行时间含义，取锁另以同一数值为等待上限，结果区分等待、执行和 processStarted。取消等待不会启动进程；取消执行需等待原命令的清理宽限。

恢复的资源检查最多等待两秒，同一阻塞的并发恢复复用当前检查。检查失败或保存/删除记录失败保留保护。运行时不使用可能复用的裸 PID 再次发起终止；重启只有已保存的阻塞事实，没有原句柄时需外部检查和用户确认。`workspace-blocks/*.resolved` 保留解除依据；未发生阻塞的普通命令不逐条建立新日志。

Esc 只等待被中断 Run 自己产生的阻塞，不等待所有成员，也不被旧 Run 的阻塞拦住纯模型对话。输入在历史提交成功后才离队，正在持久化的输入不能再次领取。已经成功的工具结果保留，未完成调用按实际终态封口。旧 Run 终态保存失败仍使群组停止，不因输入中断标记而被忽略。

Session 继续使用 Schema 4，新请求配置字段可选；旧记录缺少时保持未知。恢复不扩大成员能力、三种权限模式、十个执行并发或 worktree 边界。
