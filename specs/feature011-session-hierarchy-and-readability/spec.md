# Feature 011：会话归属与核心链路可读性

状态：实施中

## 开发者速览

> **一句话**：让一次主 Agent 协作拥有清楚的会话与产物归属，并降低核心代码的阅读和修改成本。<br>
> **核心做法**：新成员历史收进根会话目录，浏览按根组织，集中状态、时序和重复规则。<br>
> **边界**：保留两个 package、既有执行与权限合同；旧历史原位兼容，不做批量迁移。<br>
> **风险 / 未验证**：混合布局清理已通过本地验证；运行核心与 TUI 的改造和验证尚未完成。<br>
> **当前 / 请审阅**：Plan 01 已实现并通过定向审查；已授权连续完成后续 Plan，并在每个 Plan 审查后提交。

## 问题与依据

分析基线为 `main @ 865baac`。2026-09-09 的一次实际任务由一个主 Agent 和三个只读 SubAgent 完成；成员分别负责水星与金星、地球与火星、木星与土星，均正常结束并被释放。四份日志已有正确的 `sessionKind` 和 `rootSessionId`，但目录平铺，直接查看时难以辨认根会话；TUI 的主会话列表与成员历史入口也缺少连贯的归属展示。

关键链路扫描同时发现：Runtime 依赖延迟回调补齐装配，Tool 批次协议分散，Session 追加混合多种入队和锁交接状态，Context 多次转换同一组历史，MCP 工具计划依赖隐含请求快照，Git 恢复需要跨函数解释阶段，TUI 多处同步呈现状态。部分注释只翻译变量或条件，部分注释承诺了实际由下游完成的行为。

本 Feature 包含两类结果：会话归属与浏览的行为调整，以及保持既有语义的代码结构、命名和注释整理。两者分别验收，目录变化本身不构成可读性改善证据。

## 已确认方向与文档边界

- 根会话承载一次用户协作，SubAgent 与 Team 成员保持各自独立的线性 Session、工具产物和取消资源。
- 目录和交互均应表达根与成员的归属；成员工具产物的存储、引用和清理必须与会话布局一并定义。
- 阅读成本整理覆盖已发现的核心链路，同时处理状态归属、调用顺序、重复规则、命名与注释质量。
- 开发者于 2026-09-09 确认方案并要求“按照流程来实现它”，授权补齐 Plan、统一 Tasks 并实施。开发者进一步明确：连续实现整个 Feature，每个 Plan 完成验证和审查后允许提交，再推进下一 Plan；推送和 PR 仍单独授权。

本稿确认并实施后，替代 [Feature 007 Spec](../feature007-multi-agent/spec.md#存储与恢复合同) 中新成员必须与根会话日期平铺的要求。当前平铺实现和历史报告保留其事实；实现完成后再同步 [技术基线](../../docs/technical-baseline.md) 与使用说明，不提前写成已实现能力。

## 用户流程

1. 用户新建或恢复根会话，能够直接辨认当前主会话及其成员概览。
2. 主 Agent 委派 SubAgent 或组织 Team；每个成员显示名称、身份、任务摘要和状态，执行过程归属于该成员。
3. 用户从当前根会话使用 `/agents`、`/agent result <id>` 和 `/agent artifact <id> <artifactId>` 查看成员结果、完整历史和产物；成员详情始终显示所属根会话。
4. 成员结束或被释放后，用户仍可回看记录。重开根会话只恢复已有事实；显式继续才创建新的 Run。
5. 维护者从公开 Agent 行为或 TUI 命令入口阅读代码，能够找到状态持有者、执行前检查、持久化时点和失败收口位置，不必根据散落的赋值猜测协议。

## 会话与浏览合同

### 根与成员

- 保留 `primary | subagent | teammate`；根的 `rootSessionId` 为自身 ID，成员直接指向根。成员仍不能创建其他 Agent，不增加任意深度的会话树。
- 根日志保存用户对话与协作事实，成员日志保存自己的输入和执行。浏览聚合不把成员完整消息复制进根日志或根模型上下文，也不改变内部输入的授权身份。
- `/resume` 继续只列可恢复的根会话。打开根会话时显示明确的主会话身份和成员概览；无成员时保持现有单 Agent 使用方式。
- 全屏 TUI 将成员执行信息按成员归组，默认收拢过程明细，展示任务、当前状态和已有结果摘要；完整历史与产物沿用上述命令按需查看。查看成员不切换当前可输入的根 Session，不隐式启动、继续或提升成员权限。
- `/agents` 与成员详情展示根 ID、成员名称与 ID、成员种类、任务摘要和状态。缺少名称或结果时使用 ID 或明确的缺失说明，不调用模型生成标题或推断成功。
- 纯文本入口保留清楚的根与成员来源标签，并与全屏入口使用一致的状态、失败和结果含义；两种入口各自保留合适的布局。
- TUI 通过现有 `sessions` 和 `collaboration` 控制面获得归属及摘要，不扫描 Session 目录，不持有成员运行生命周期。必要的只读展示字段在 Plan 中列明；不新增模型消息、Provider 类型或内部循环步骤的公开出口。

### 预期数据目录

下图为本 Feature 实施后新创建的根与成员布局。根目录沿用根 Header 的 UTC 创建日期、时间戳和 ID；成员目录使用稳定的成员 Session ID，名称和 Team ID 只作为记录内容。

```text
data/
├─ conversation/                         # ANTHIAS_SESSION_DIR 可覆盖整个历史数据根
│  ├─ session-locations.json             # 可重建的 ID 定位缓存
│  ├─ .maintenance/                      # 既有使用标记、锁和清理恢复数据，继续按 Session ID 管理
│  └─ <根创建UTC日期>/
│     └─ <根创建时间戳>-<rootSessionId>/
│        ├─ session.jsonl                # 主会话和协作事实
│        ├─ session.index.json           # 当前 Session 的可重建恢复索引
│        ├─ artifacts/                   # 根 Agent 的工具输出原文，按需创建
│        │  └─ <artifactId>.txt
│        └─ members/                     # 按需创建，不另建 Team 专用历史目录
│           └─ <memberSessionId>/        # SubAgent 与 teammate 使用相同存储形态
│              ├─ session.jsonl
│              ├─ session.index.json
│              └─ artifacts/
│                 └─ <artifactId>.txt
└─ worktrees/                            # ANTHIAS_WORKTREE_DIR 独立覆盖，继续保存受管代码工作区
   └─ <rootSessionId>/<worktreeId>/
```

- 成员次日创建或继续执行，仍留在原根目录；成员 Header 保留自己的实际创建时间，不为目录归属伪造时间。
- 每个 Session 只追加自己的日志、更新自己的恢复索引并写入自己的产物目录；根与成员不共享一个日志写入器或产物额度。
- Header 的身份与根归属是校验依据，根协作记录提供任务、状态及成果事实。目录嵌套不能代替身份校验，也不授予权限。
- 日志继续使用 Schema 3，Schema 1/2 读取兼容保留。目录布局与日志 Schema 分别表达，不因移动存储位置就重写消息格式或持久 ID。

### 工具产物、项目文件与临时输出

| 内容 | 存放与持有者 | 引用及清理合同 |
| --- | --- | --- |
| 普通有界 ToolResult | 执行该工具的 Session JSONL | 直接保存结果，不为短输出额外创建产物 |
| 因输出预算需要回读的原文 | 执行 Session 的 `artifacts/<artifactId>.txt` | 保留 ToolCall 关联、完整性和大小；会话消息成功引用后才作为可回读结果发布 |
| 命令尚未交付的长输出 | 该次命令独占的临时文件 | 沿用工具内部有界收集，结果收敛负责保存及释放；保存失败、取消和清理不确定分别如实返回 |
| 工具创建或修改的代码、截图及其他项目文件 | 工具实际指定的成果路径，通常在 Workspace 或受管 worktree 中 | 属于工作成果，不因会话历史清理而删除；路径访问和成果交付继续使用现有权限、Git 和工作区合同 |

当前 Session 的 `read_artifact` 继续只读取自身已经引用的产物。根检查成员产物使用成员 Session ID 与产物 ID，并确认产物存在于该成员历史引用中；无需复制进根产物目录。Team 成员间保持现有结果分享范围，不因共用根目录开放彼此完整历史和产物。

保持当前单产物、单 Session、回读和输出预算。产物持有者始终是创建它的 Session；结果被根引用或成员结束后不更换持有者。临时 `.part`、未引用文件及不完整原文沿用现有失败和清理规则，不冒充已完整交付的结果。

### 旧历史与混合布局

- 已有日期平铺成员和旧格式日志原位兼容；只读查询不改写或搬迁它们，不新增全库批量迁移。
- 已有成员显式继续时仍使用原位置。旧根显式继续后创建的新成员采用嵌套布局；需要旧格式升级时，仅沿用既有的显式打开兼容路径。
- 因此同一根可以包含旧平铺成员和新嵌套成员。定位、浏览、恢复、产物回读和组清理均必须覆盖这一情况，不能只查根目录内的成员。
- `locations.ts` 集中受管布局识别、路径校验、候选枚举和按 ID 定位。列表、历史和分组复用这些规则，分别保留列表容错、严格打开及清理完整性要求。
- 缓存缺失、损坏或陈旧时可以按受管布局重建；缓存不是身份或授权权威。同一 ID 出现多个无法确认权威的位置时返回明确冲突，不按修改时间或目录深度选择一个继续写入。

### 失败、恢复与组清理

| 情况 | 必须表现 |
| --- | --- |
| 成员目录、日志或产物缺失、损坏 | 保留可读的根历史与协作摘要，定位到受影响成员；详情或回读明确失败，不显示为空历史或成功结果 |
| 根与成员 Header 归属不符、路径越界或定位冲突 | 拒绝受影响的打开、写入或产物读取；不把它自动挂到当前根会话 |
| 创建成员中断 | 保留已有创建意图与诊断；重开不自动重新创建目录、模型或工作区 |
| 历史查询达到扫描边界，组成员无法确认完整 | 如实给出不完整诊断；清理保守保留整组 |
| Workspace 或 worktree 已不存在 | 日志与产物仍可只读查看；执行恢复按既有资源检查返回结果，不重新制造原工作成果 |
| 任一根或成员仍被使用、有未交付资源或状态不确定 | 整组保留，不能因根当前空闲或成员已释放就删除其历史 |
| 嵌套或混合布局的清理中断 | 可恢复识别已移动和未移动内容；嵌套父子源路径去重，不重复搬动成员或删除未完成组，不删除 worktree、分支或项目文件 |

只读浏览、缓存重建和恢复展示不调用模型、不重放工具、审批或 Git 副作用。成员释放与历史删除仍是独立动作。

## 核心链路改造合同

本节要求改变维护方式，保持当前用户行为、权限、事件含义和持久化事实。发现功能缺陷或需要改变既有语义时先记录并回到讨论，不借可读性整理扩张范围。

| 链路 | 必须达到的阅读与职责结果 |
| --- | --- |
| Runtime 装配 | 根与成员的共享资源、独占资源和可用时点在装配入口可见；构造期间不会调用尚未绑定的回调，禁止依赖读者自行推断的未初始化循环捕获 |
| 协作控制 | 集中直接控制与经 Tool 执行的动作分类，并明确各自的 Run、审批、持久化与取消合同；停止、等待和查询仍能按既有忙闲规则工作 |
| Tool 批次 | 普通生成循环只调用一个完整批次行为；资源冲突、顺序屏障、审批与执行前复核、四并发、源序结果提交和取消补齐仍由同一批次协议协调；实时事件反映实际发生顺序 |
| Session 追加 | 追加接受、刷盘成功、Run 封口和 lease 释放各有明确含义；写锁、队列和持久状态有单一持有者，运行中与空闲追加复用同一持久化规则 |
| Context 投影 | 对同一请求明确采用的记录、来源和检查点；成员输入、来源更新及完整 Tool 组的位置统一计算，摘要选择复用同一分组依据；不由多个阶段反复补位置或依赖隐含数字位置约定 |
| MCP 工具 | 当前请求可见 Tool、预算筛除及连接 generation 绑定成明确快照；创建执行计划消费对应请求的快照，不能被另一次投影的闭包状态覆盖；执行前仍复核当前权限与连接有效性 |
| Git 集成 | 集中解释 intent、staged、conflicted 等既有阶段和实际副作用的关系；继续与中止从同一处取得恢复判断，持久化前后顺序及不确定结果保护保持不变 |
| TUI 呈现 | 当前 Run、Assistant 和详情的呈现数据由少量操作独占更新；组件正文、详情索引和所属成员不通过多处赋值保持一致；纯文本与全屏共用必要的状态和诊断文案，各自持有布局 |
| 命令发现 | 顶层及子命令的名称、参数提示和帮助使用同一份声明信息；参数解析与 Agent 调用保持显式，不新增通用命令执行框架 |

Context 重构必须保留真实用户与内部来源的身份差异、当前 Run Reasoning 的既有处理、来源撤销、完整 Tool 组、压缩候选校验与先落盘后采用。Session 与 Tool 重构必须保留副作用前事实记录、单次授权约束、取消及关闭收口。执行可靠性、Full Access 和并发规则以当前实现及 [Feature 010 Spec](../feature010-agent-execution-reliability/spec.md) 为基线，不退回旧版的纯只读并发或请求次数截止。

### 命名与注释

- 名称说明实际对象、所有权和阶段。会更新本次请求快照的行为不能仅用容易被理解为纯转换的名称；目录版本与日志 Schema 不能用同一个含混判别值让调用者猜测。
- 删除仅翻译字段、条件、循环或返回值的注释；不以注释覆盖率、文件行数或统一函数模板作为目标。
- 在装配顺序、并发与终态竞争、持久化提交点、权限来源、资源转交和反直觉筛选处保留简短中文注释，说明原因、必须保持的条件及失败后果。
- 注释承诺限于当前函数实际保证的行为。若保证由下游完成，应在真正的保证点说明，并让上游合同准确反映其中间结果。
- 重点核对现有的“获取 ToolCall 列表”“已经压缩”、产物字段逐项翻译、`includeAgentInputs` 的分组承诺及命令目录的统一范围；同时检查本次触及链路中的同类问题。
- 已经解释必要顺序的注释随实现保留或更新，例如授权撤销先失效再写盘；源码注释不提 Feature 或 Stage 编号，不保留已不成立的旧流程说明。

主要职责迁移：`agent.ts` 的 Runtime 装配进入 `runtime.ts`；`agent-loop.ts` 的 Tool worker、顺序控制与提交进入 `tool/tool-batch.ts`；`session/index.ts` 的追加与 lease 状态进入 `session/writer.ts`，其已提交事实仍只有一个持有者；`context/assembly.ts` 的职责并入 `projection.ts` 并移除旧文件，`selection.ts` 中的历史关联与成员输入排列同步归入投影；MCP 的隐含可见工具集合与 Git 集成恢复分别进入对应新文件；TUI 的关联状态更新进入 `presentation.ts`，帮助和补全声明进入 `command-definitions.ts`。

`event-text.ts` 只复用已经重复的展示信息，不复制 AgentEvent 总线或另建事件状态机；`presentation.ts` 不再维护一份能独立修改的 Agent 业务状态。`tool-snapshot.ts` 及其他新增文件均为 Agent 内部细节，不从 package 入口导出。其余源码、测试和稳定文档按真实消费者同步，不进行无关目录重排。

## 验收标准

以下按完整场景组织，可复用同一组确定性会话和临时工作区，不要求每行新增独立测试。

| 编号 | 通过条件 |
| --- | --- |
| A01 | 新根与三个成员形成嵌套布局；SubAgent 和 teammate 均覆盖，跨日成员仍归原根，Header 身份与创建时间正确 |
| A02 | 根与成员的短结果仅入自身 JSONL，超限原文进入自身产物目录；并发保存不串引用、不共享 Session 额度、不覆盖其他成员 |
| A03 | 根可按成员与产物 ID 回读，错误成员、未被消息引用的产物及越界路径被拒绝；成员间原有分享范围保持 |
| A04 | 根入口直接显示主从归属，成员过程按来源收拢，完整历史可按需查看；纯文本与全屏均不混淆来源，查看不改变当前根输入目标 |
| A05 | Schema 1/2/3、旧平铺、新嵌套及同根混合布局均可按合同定位和恢复；只读前后旧日志与产物不变，已有成员继续不搬迁 |
| A06 | 定位缓存损坏或失效可恢复；重复 ID、Header 冲突、缺失成员和扫描不完整有明确诊断，不能因此丢失根的可读历史或误清理 |
| A07 | 嵌套及混合组清理保护所有活动 Session、未知状态和未交付成果；中断后可恢复，父子路径不重复处理，项目文件、worktree 与分支保持 |
| A08 | 关闭、停止和重开不重放模型或工具副作用；产物保存失败、取消及临时资源释放保持如实结果 |
| A09 | Runtime 构造与成员生命周期、直接控制与 Tool 控制路径都有清楚入口；忙时查询/停止、审批路由、共享资源关闭保持原行为 |
| A10 | 独立动作并发、冲突读写顺序、顺序屏障、四并发、执行前复核和源序结果归档保持；取消补齐和失败收口不依赖新的外部调用 |
| A11 | Session 入队/落盘/封口/释放竞态保持正确；Context 同文消息身份、完整 Tool 组、来源更新/撤销、压缩失败和恢复投影保持正确 |
| A12 | MCP Tool 定义与后续计划绑定同一请求快照，预算筛除、断连和 generation 变化仍被识别；Git intent、不确定副作用、staged/conflicted 的继续与中止保持可恢复 |
| A13 | TUI 的 Assistant 增量、工具详情、成员归组、历史恢复和退出正常；帮助、补全与实际命令参数一致，Windows 路径与现有按键能力保持 |
| A14 | Report 为上述改造链列出入口、真实消费者、状态持有者、持久化时点及失败收口的前后对照，并说明公开面变化；仅搬文件、增加转发层、缩短行数或增加注释均不算完成 |
| A15 | 本次触及链路的机械、过期和承诺错位注释已清理，关键不变量就近说明；完成定向验证、最终统一门禁与一次独立审查，无重复运行同版本同环境已有可信验证 |

验证使用确定性 Model Stream、本地临时仓库及本地 MCP 测试能力；真实 Provider、外部网络或现有用户数据的破坏性演练需另行授权。`data/conversation/2026-09-09` 仅作为只读依据，不直接迁移或清理。Plan 需给出定向命令、必要的失败注入及各独立增量的停止点；源码改造与目录结果均完成后才可声称整个 Feature 已实现。

## 不在范围内

- 旧历史批量迁移、历史正文合并、成员完整历史自动注入根上下文、任意层级 Agent 派生。
- 新增权限模式、改变成员授权来源、扩大 Team 分享权限、改变模型重试、压缩或 Git 成果语义。
- 把所有工具输出都保存为产物、跨 Session 内容去重、统一成果仓库或新的组级产物配额。
- 新 package、Host、Desktop、OS 沙箱、数据库、通用 Registry/Manager、调度框架或第二套事件系统。
- 全仓格式化、所有模块套用同一目录模板、用固定行数或注释数量作为架构门槛，以及本次链路之外的重写。
- 未经单独授权的提交、推送、PR 和真实 Provider 验证。
