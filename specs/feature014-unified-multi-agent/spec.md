# Feature 014：统一多 Agent 持续协作

状态：已实现

## 开发者速览
> **一句话**：将 SubAgent 与 Team 合并为由根 Agent 统筹的持续协作群组。<br>
> **核心做法**：统一成员、持久邮箱、受管共享笔记和可取消的工作区写入协调。<br>
> **边界**：总执行并发十个，默认共享工作区，根 Agent 按需选择工作树。<br>
> **风险 / 未验证**：关键并发与恢复已通过本地验证；真实模型与人工终端体验未验收。<br>
> **当前 / 请审阅**：已按先 Spec 后实施的授权完成；验证证据见 Report，待开发者验收。

## 问题

现有 SubAgent 与 Team 分别持有短任务和持续协作生命周期，可写成员又隐式创建工作树。用户需要持续向同一成员插入对话、了解进度并控制成员，同时通常希望大家直接在当前工作区协作。现有文件写入只有单次准备快照与单批调度，不能防止不同 Agent 根据旧内容覆盖彼此。Feature 013 的停止、继续、再次停止竞态也会破坏邮箱自动唤醒的暂停语义。

## 用户流程

1. 用户向根 Agent 提出工程任务，根 Agent 直接创建普通成员并分配任务；首次创建即形成该根 Session 的唯一隐式群组。
2. 成员默认使用根工作区，各自持有 Session、上下文和 Run；完成一轮后进入空闲，后续任务或消息继续使用原成员。
3. 根与成员通过邮箱传递问题、结果和协作请求，通过一份共享 Markdown 补充长期协作内容，通过群组快照查看任务、状态和工作区。
4. 用户可以暂停与继续成员；根 Agent 可以管理成员、关闭并明确重新打开成员。普通成员不能操作其他成员的生命周期。
5. 需要隔离时，根 Agent 显式创建或选择受管工作树，再为停止中的成员绑定工作区；已有 Git 成果交付流程继续可用。

## 已确认决定

### 群组、执行与权力

- 一个根 Session 对应一个群组，不再要求单独创建 Team，不保留两套成员行为，也不允许成员递归创建成员。
- 同时执行的 Agent 总数最多十个，其中为根保留一个位置，成员最多九个。空闲、暂停、关闭的成员不占执行位置；超出的可执行工作等待调度，不能绕过限制。
- 权力顺序为用户、根 Agent、普通成员。根独占成员创建、正式任务分配、暂停、恢复、关闭、重新打开、工作区绑定与 Git 成果交付。用户可以约束或停止根和成员。
- TUI 或公开协作入口中由用户直接提交的正式任务，先在根日志保存带真实来源的 `user_request`，供 AutoAllow 核验；模型工具调用不能自行制造此来源。
- 发送者身份、所属根与任务来源由运行时绑定。成员消息、共享笔记和工具输出均不是用户授权，不能提升权限或覆盖根任务。
- 成员可以更新自己的任务进度、发送消息、查看群组快照和其他成员公开结果。根可以查询完整成员历史；普通成员不能借群组查询读取其他成员的完整历史或私有产物。

### 邮箱与自动唤醒

- 根与每个成员各有持久、有限的收件队列。消息记录稳定标识、来源、发送者、接收者、时间、任务关联、内容及投递状态；重复标识不得重复消费，不同内容复用标识必须拒绝。
- 每个接收者最多保留 32 条待处理消息，单条正文最多 16 KiB；溢出明确失败，禁止静默丢弃。历史消息不计入待处理容量。
- 运行中的接收者在完整 Tool 批次结束后的安全点消费消息，不打断工具副作用；空闲成员收到消息自动进入调度。多个消息可以合并处理，根正式任务优先于普通协作消息。
- 消息进入 Session 上下文后才确认消费，持久化顺序必须支持失败与重启后的去重。消息本身不要求自动回复确认，避免成员之间产生无用循环。
- 暂停成员继续收件但不能被唤醒。用户暂停必须由用户继续；根暂停可以由根继续。根任务结束后关闭该任务的自动唤醒，迟到消息仅保留历史；用户明确继续群组才重新调度。
- 群组共享当前任务的三十分钟时限，消息与成员重复唤醒不能重置时限。应用重启只恢复历史和状态，不能自行恢复模型执行。

### 共享笔记与状态

- 每组唯一一份 `shared-notes.md`，位于根 Session 目录，独立于所有工作树。它通过受管协作工具访问，普通文件工具不能绕过 Session 目录保护。
- 所有成员可以读取和追加；追加串行提交并记录作者与修订。根可以携带预期版本重整全文，过期修改拒绝。
- 笔记是协作内容，不是任务、权限或成员状态的控制文件。修改笔记不自动广播或唤醒全体成员；需要通知时发送邮箱消息。
- 群组状态至少展示成员当前任务、运行阶段、暂停/关闭、等待批准或资源、工作区和最近活动/阻塞原因。状态由运行时产生，不依赖模型自行声称完成。

### 三种权限模式

| 模式 | 行为 |
| --- | --- |
| 请求批准（`agent`） | 只读请求直接执行；代码写入、命令和其他外部副作用逐次人工批准。 |
| AutoAllow（`auto_allow`） | 有副作用的请求由审核 Agent 自动审核，普通、必要且符合用户目标的操作尽量放行；极高风险或需要用户决定的操作转人工。审核失败不等于批准。 |
| 完全访问（`full_access`） | 不进行人工或模型批准；仍遵守所有权、明确禁止、取消、并发与资源约束。 |

- 组内通信、状态更新和受管共享笔记在三种模式下自动允许；这些例外不扩展到任意代码文件或外部操作。
- 运行时删除 Plan 模式。成员只读能力作为独立约束，不再用全局模式模拟；根不能把自己没有的权限授予成员。
- 显式用户禁止与现有受管工作区授权继续生效；成员内容不构成根用户授权。
- 历史 Session 中的 `plan` 权限记录和 `subagent` / `teammate` 标记仍可读取。存储兼容标记不再决定运行时成员行为，避免仅为改名迁移整份历史。

### 工作区与并发写入

- 成员默认可写并绑定根工作区，根可显式将成员限制为只读。是否可写与是否使用工作树独立；可写成员不得隐式创建工作树。
- 根可以显式创建固定提交上的受管工作树或绑定已有受管工作树。切换前必须停止该成员，检查原工作区和目标资源；不能隐式迁移未提交修改。
- 工作树不自动复制未提交内容、依赖、凭据或后台服务。精确路径提交、成果应用、冲突继续/中止和安全移除沿用受管 Git 能力。
- `read_file` 返回完整原始字节的 SHA-256 内容版本，格式为 `sha256:<摘要>`；分页读取仍对应整个文件同次读取的版本。空文件摘要与文件不存在必须区分。
- `edit_file` 与覆盖型 `write_file` 必须携带模型实际读取的 `expectedVersion`。新建文件显式使用 `missing` 前提。不得用工具准备时的新快照代替模型读取版本，否则旧内容仍可能覆盖新内容。
- 同一实际文件的受管写入串行，不同文件可以并行；路径别名、大小写和真实路径必须归一，同一文件身份不能绕过协调。等待可取消，不在模型思考或人工批准期间持锁。
- 取得写入权后重新检查预期版本、文件/父目录身份、权限与取消，再原子替换。锁必须覆盖最终检查到替换的完整区间。版本过期只拒绝本次修改，Agent 需重新读取、调整并按当前模式重新批准，不自动合并或盲目重试。
- 内容恢复为完全相同字节时，摘要相同属于有效匹配；历史顺序由 Session/Git 记录，不把哈希当作递增事件编号。
- `execute_command` 在所属工作区占用独占写入阶段：等待已有文件写入结束，阻止新的同区文件写入和其他命令，直到命令资源结束。读取、思考、消息仍可继续；不同工作树可以并行。受管 Git 变更也必须与相关工作区写入协调。
- 以上覆盖本进程受管操作，不声称是 OS 沙箱，也不保证外部编辑器、任意脚本越界写入或其他进程遵守内部锁。

### 暂停、关闭与恢复

- 重复停止必须有效：停止、继续、再次停止发生在旧 Run 清理期间时，最后一次停止取消尚未兑现的继续请求。
- 暂停先禁止自动唤醒，再取消执行与待批准/待锁请求，等待当前 Run 清理；保留历史、任务和邮箱。
- 关闭先拒绝新输入和唤醒，取消启动/执行/批准/资源等待，等待清理完成后才标记关闭并释放执行资源。清理未完成不能提前宣称关闭或删除目录。
- 关闭成员保留 Session、公开结果、未消费消息和工作树；新消息明确拒绝。根可以显式重新打开，重新检查原 Session 与工作区后恢复调度。普通消息不能重新打开成员。
- 用户停止群组时同时停止根与成员，群组暂停门闩只能由用户继续解除；根不能借新建成员绕过。根因失败或取消终止时收束成员执行，不让迟到异步结果恢复调度。根正常完成只关闭后续自动唤醒，已启动成员 Run 可以在原时限内自然收尾。应用退出释放资源并保留原暂停/空闲状态，执行中成员恢复为中断；显式关闭成员才保存 closed。

## 不在范围内

跨机器/跨进程群组、远程消息服务、独立数据库、任意共享文件、自动代码合并、OS 沙箱、工作树环境自动搭建、递归成员、专用工程验证平台、真实模型冒烟、推送与 PR。

## 验收标准

1. 统一入口创建的成员可连续执行任务与对话，默认共享根工作区；九个成员执行位置饱和时排队，不超过含根十个的上限。
2. 普通成员只能执行获准的组内行为，不能创建/管理成员、伪造用户授权、读取同伴完整私有历史或接管根任务。
3. 邮箱覆盖忙碌安全点投递、空闲唤醒、暂停不唤醒、容量拒绝、幂等消费、关闭拒收、重启不执行和根任务结束后的迟到消息。
4. 共享笔记覆盖并发追加无丢失、作者记录、根重整版本冲突、普通成员重整拒绝和普通文件工具无法直接写入。
5. 三种模式在 Agent 与 TUI 一致；只读成员独立受限，旧权限记录可读，内部通信自动允许，外部副作用符合批准合同。
6. 文件测试覆盖同版本竞争只成功一次、排队后重新核验、同一真实文件别名、新建冲突、空文件/缺失区别、等待取消、不同文件并行和命令排他。
7. 暂停与关闭覆盖停止/继续/再停止、启动期间关闭、待批准关闭、待资源关闭、关闭后显式重开、失败不提前释放所有权。
8. Git 与历史恢复保留已有有效行为；根显式选择工作树，可写成员不自动创建工作树；历史 SubAgent/Team 可被统一展示。
9. 通过定向确定性测试、类型/静态检查和最终完整本地回归；文档如实区分已实现、用户待验收与未做的真实环境验证。
