# Feature 014 实施方案

状态：已实现

## 开发者速览
> **一句话**：按统一协作合同完成运行时、工具、TUI 与恢复链路。<br>
> **核心做法**：先建立写入与暂停基础，再打通持续成员、邮箱、笔记和三种权限。<br>
> **边界**：沿用两个 package 与本地 Session；只做本地确定性验证。<br>
> **风险 / 未验证**：成员关闭与投递的异步顺序、共享 Git 写入和旧历史兼容。<br>
> **当前 / 请审阅**：三个增量已连续完成，完整门禁通过，待开发者验收。

## 当前基线与范围

基线为 `main` 的 `7ea441a3d08a58eec7d825816976d1a68dcc64fa`。已有用户修改是 `agent-loop.ts` 的工具调用注释，必须保留且不纳入本 Feature 提交。现有 SubAgent/Team、Session 输入安全点和受管 Git 已有定向测试；当前阶段不重复运行相同基线测试。

实施以 [Spec](spec.md) 为准。职责保持在 Agent 内：协调层持有群组、调度和权限来源；单 Session 执行器继续持有模型与 Run；文件工具持有内容版本与原子写入；TUI 只调用行为与呈现状态。

## 实施步骤

### 增量一：安全写入与停止基础

建立共享的文件/工作区写入协调；读取暴露内容版本，写入携带预期版本并在锁内重核；命令与受管 Git 对相关工作区独占。修复停止、继续、再次停止时旧 Run 结束恢复执行的竞态，形成可独立验证的基础。

### 增量二：统一持续协作

将成员生命周期统一为持续 Session，去除可写隐式工作树，增加九个成员执行位置与排队。将任务、邮箱和共享笔记分别收束在现有协作目录内；根控制成员与绑定，成员仅获通信和自身进度能力。接入忙碌安全点消费、空闲调度、暂停/关闭拒绝唤醒、重启只恢复与群组期限。

### 增量三：权限、交互与完整验收

移除运行时 Plan 模式，独立表达成员只读约束，落实内部协作自动允许。更新工具描述、系统提示与 TUI 入口/状态；兼容旧 Session 和协作记录。完成定向测试后运行一次完整本地回归与静态检查，开展独立审查并修复有效问题，更新稳定文档和 Report。

上述增量按依赖衔接，边界独立的文件工具、权限表层实现可以并行；相同代码和环境的可信定向测试不重复执行。用户已授权完整 Feature，不在增量完成后等待重复确认。仅在有独立验收价值且验证完成时提交，不推送。

## 文件职责

- `multi-agent/index.ts`：统一根控制、群组快照、期限与调用权限。
- `multi-agent/members.ts`：成员持有、执行排队、暂停/关闭/重开、工作区绑定。
- `multi-agent/tasks.ts`：任务状态；替代原 `agent-team.ts` 的双重群组行为。
- `multi-agent/mailbox.ts`、`shared-notes.ts`：持久投递与受管共享内容，不复制 Session 执行循环。
- `tool/workspace-access.ts` 与现有文件/命令/Git 工具：可取消写入协调与版本前提。
- `runtime.ts`、`session-agent.ts`、权限模块：共享依赖接线、输入顺序与三种模式。
- 现有 TUI 协作/权限/命令视图：统一成员命令与状态显示。
- Session 恢复/清理只做新状态兼容所需调整；不为存储术语改名迁移历史全文。

## 验证

1. 写入协调使用临时文件、受控 Promise 和本地命令证明竞争、取消与原子写入；不只测试辅助函数返回值。
2. 协作通过 Agent Interface 与确定性 Model Stream 覆盖任务、邮箱、权限、暂停/关闭和恢复。
3. TUI 验证公开命令解析、快照与批准呈现；Git 使用临时仓库验证绑定和成果操作。
4. `pnpm check` 与 `pnpm test` 完成最终静态检查、构建和完整测试。真实模型、外部网络、凭据和主观终端体验不在验证结论内。
5. 独立审查对照 Spec，聚焦越权、竞争、资源释放与遗漏。已有可信结果不重复跑；修复后补受影响的验证。

## 风险、停止条件与报告

用户目标或公开语义需要改变时回到讨论；工具环境失败先诊断，不静默缩减范围。用户已有文件改动不得覆盖。关闭失败保留所有权和资源，不伪装成功。Report 汇总实际能力、调用链、关键边界、命令结果与未验证项，完成后标记已实现，等待用户验收。
