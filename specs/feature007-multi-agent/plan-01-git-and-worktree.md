# Feature 007 Plan 01：Git 与 worktree

状态：已实现

## 开发者速览
> **一句话**：交付可查询、隔离、保存和集成本地成果的 Git 能力。<br>
> **核心做法**：结构化参数、固定提交基线、操作前记录意图，执行后核对真实状态。<br>
> **边界**：本地有效普通仓库；不复制未提交修改，不调用远端，不默认强制删除。<br>
> **风险 / 未验证**：Git 与 JSONL 无跨文件事务，未知结果必须保留诊断。<br>
> **当前 / 请审阅**：Git/worktree 已完成本地验证，证据见统一 Report。

## 当前基线与范围
基线 main / 596c2cb。保护现有产品方向文档修改。新增 git 内部 Module，使用 Git 可执行文件和现有权限/Tool Loop；不新增 package。
Session 增加明确版本的协作事实记录和只读历史行为，为实际 Git 资源恢复服务。

## 实施
1. 实现仓库身份、ref 固定和有界查询，Git 调用使用参数数组与明确 cwd。
2. 管理 worktree ID、路径、公共 Git 目录、分支、基线与结果；创建/检查/移除及恢复核对。
3. 实现精确暂存提交、提交 ID 集成、冲突继续/中止，保护目标 HEAD、暂存区与未提交修改。
4. 接入工具校验、审批、操作日志和取消，TUI 可查看并调用这些已定义行为。
5. 写入运行数据覆盖配置，保持 Session 和 worktree 目录独立。

## 验证与停止条件
定向临时 Git 仓库验证：dirty 基线、目录隔离、部分暂存拒绝、目标变化、冲突与移除保护、取消。只用临时仓库的测试提交；不提交 Anthias。发现批准内容与动作不一致或无法证明路径归属时拒绝该动作，保留数据并报告。
