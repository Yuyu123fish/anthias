# Feature 007：MultiAgent 与 Git worktree

状态：已实现

## 开发者速览
> **一句话**：主 Agent 可以在独立工作区委派任务，并通过团队持续协作完成本地交付。<br>
> **核心做法**：复用 SessionAgent，增加一层成员协调、结构化 Git 操作和可追溯持久记录。<br>
> **边界**：同进程、最多三个成员；成员不能再创建 Agent；工作区从已提交版本创建。<br>
> **风险 / 未验证**：worktree 不提供 OS 沙箱；真实 Provider 与主观终端体验不由本地测试证明。<br>
> **当前 / 请审阅**：三个 Plan 已完成实现和本地验证，等待开发者验收。

## 问题与用户流程
实施前只有单 Session 执行，不能把独立工作交给隔离成员，也没有受控 Git 成果交付入口。主 Agent 应能查询仓库、创建 worktree、委派 SubAgent、等待并读取结果，或建立一个 Team、分派任务并交换消息，再核对和集成本地成果。

## 已确认决定
- 保留 apps/agent 与 apps/tui，同进程复用现有 Loop、Context、Tool、Permission、Skill 与已连接 MCP。
- SubAgent 完成有界任务后停止；Team 保留成员上下文，Lead 分派任务；首版一个活动 Team，和 SubAgent 共用三个成员名额。
- 只有根 Agent 可以创建成员、分配其他成员任务和修改共享 Git 状态。成员执行端硬拒绝递归创建，角色来自受管身份。
- 可写成员使用独立 worktree。基线为明确 ref 解析出的提交 ID，默认创建时 HEAD；提示未提交修改不会带入，不自动 stash、提交或复制。
- Git 提供查询、受管 worktree、精确暂存/本地提交、集成与冲突继续/中止。复用授权和副作用记录，不含远端 push/fetch、隐式 init 或任意参数透传。
- 委派、消息、结果保留根/发送 Session 与稳定消息 ID；内部输入不能成为真实用户授权。审批来自根真实用户记录，统一路由至来源成员。
- 普通消息入队，下一次模型请求前消费，不唤醒空闲成员；明确任务才启动。等待有界、可取消，空闲不发模型请求。
- Session 继续日期平铺 JSONL，新增格式明确版本化；主 Session 保存协作和 Git 事实，成员保存自己的执行。索引可重建。
- 默认代码目录为 Anthias data/worktrees，历史为 data/conversation；二者独立覆盖配置。历史不放入 worktree。
- 查看历史不依赖工作区存在；重开不自动启动成员；显式继续核对原资源后创建新 Run，不重放不明副作用。
- 历史清理按根和成员成组判断，未交付或不确定的成果保留；历史清理不能删除 worktree 或分支。

## 生命周期与权限
成员状态为准备、运行、空闲或已结束/中断；任务状态为待执行、执行中、完成或阻塞。成员完成、结果集成、worktree 移除分别记录。全局停止取消当前整组模型、工具、审批和等待；资源结束后才能回收目录。正在执行的成员阻止会话/权限切换；空闲 Team 成员继续下一任务时同步根当前权限。

默认限制：三个活动/保留成员；单任务沿用十二次响应请求；全组一次用户任务最多六十次模型请求、三十分钟；每个成员最多三十二条待收消息，每条最多 16 KiB，结果摘要最多 16 KiB。限制触发给出可读原因，不静默丢消息。所有真实模型调用计入组预算。

Git 操作先保存意图，再执行并核对结果；异常退出后检查实际 Git 状态，不自动重试。非仓库、没有 HEAD、裸仓库和含子模块的写入工作区明确返回不支持原因；只读委派仍可用。不同 worktree 的验证必须说明实际受测版本。

## 验收
1. 两个可写成员从同一固定提交进入不同目录，互不覆盖，脏主目录修改保持原状且不带入。
2. 成员伪造创建调用被拒绝，委派原文不会成为 AutoAllow 用户授权。
3. Git 查询、精确提交、集成、冲突处理和安全移除可在临时本地仓库完整执行。
4. SubAgent 可查看、等待、停止、读取结果和显式继续；根停止能够收口成员。
5. Team 可建立/关闭、加入成员、分派与更新任务、定向消息；消息不无故唤醒成员。
6. 根/成员/消息/成果可由日志恢复，缺失 worktree 仍可读历史；重开不会恢复旧副作用。
7. 旧 Session 可读，索引和组清理不破坏历史，待交付工作区被保护。
8. TUI 通过同一 Agent Interface 显示协作、来源审批和失败，原单 Agent 行为继续成立。

## 存储与恢复合同

新 Session 使用 Schema 3。Header 中 `sessionKind` 取 `primary | subagent | teammate`；根的 `rootSessionId` 等于自身 ID，所有成员直接指向根，不产生嵌套归属。保留原来的 UTC 日期平铺目录，成员历史与根历史同级，无数据库或第二套目录注册表。

根 JSONL 的 `coordination` 记录分别保存 member、team、task、delivery、worktree 与 git_operation 事实；成员 JSONL 的 `agent_input` 记录保留 messageId、rootSessionId、fromSessionId、kind 和正文。真实用户 `message` 记录与内部输入分离；跨根授权引用显式保存授权 Session ID。模型输入可以投影这些来源，AutoAllow 不把投影当成真实用户记录。

只读历史支持 Schema 1/2/3，不修复或升级原文件；显式打开旧 Session 时按兼容路径升级，保留 ID、创建时间和 Workspace。根日志和成员日志之间不承诺数据库事务：投递按“根入队 → 成员输入落盘 → 根确认送达”顺序执行；稳定消息 ID 保证重试不重复追加。未完成创建或 Git 意图保留诊断，重开不会自动重试。

恢复只重建成员摘要、任务、队列和受管资源记录，不重新执行。显式继续已有成员时检查原 Session 和工作区，随后开始新的 Run；原 Team 已结束时旧历史仍可读，在新 Team 中安排后续工作。会话清理按整个根组最后活动时间和资源状态判断，未知状态保守保留。
